# Preserve trust through the complete Windows package

Read [the security contract](../CONTRACT.md), architecture sections 11, 15, 18–20 and applicable release instructions. Dependency selection/updates belong to [dependency-updates](../../environment/dependency-updates/SKILL.md). The current distribution is one complete signed per-machine MSI; future MSIX and TUF research are separate unqualified gates.

For build-policy work consult the proposed [development-hardening guide](../../../../docs/windows-time-development-hardening.md); for provider onboarding, signing scope/order and publisher verification consult the [signing guide](../../../../docs/windows-time-signing-guide.md). Their research and proposed steps do not establish adopted enforcement, provider approval, production signing or clean-machine verification. Actual submission, signing and publication retain their task authorization and protected approval owner.

When packaging event-provider resources/channels or product Firewall/WFP policy, read [Windows host integration](../references/windows-host-integration.md) for immutable payload/installed-resource receipts, actual service access and traffic observations, and ownership-aware rollback/repair/removal.

1. Trace source/config/lockfile/features/toolchain → host build scripts/proc macros/native tools → linked Windows binaries → complete MSI → signed artifact → installed services/UI/helper. Keep exact identities and qualification evidence for the candidate actually delivered. `Cargo.lock` stays versionable and `target/` excluded; lockfile reproducibility is not origin trust or sandboxing.
2. Inspect build-time code execution and target/host distinction. Use isolated builds for untrusted code; signing credentials and privileged runners must not execute untrusted PR source or poisoned artifacts. Constrain CI token permissions and inspect third-party action origins/immutable revisions and cache/artifact trust. Do not add workflows or choose dependency pins merely because this skill discusses them.
3. Verify selected final PE mitigations, DLL/import/load paths, protected installation/data ACLs and actual service tokens. Compiler flags and manifests are inputs, not proof of emitted/effective behavior. Matching the project target, native runtime and installed package matters; a Linux build cannot qualify those boundaries.
4. Keep one product/version/Installed apps entry and one lifecycle for UI, engine, broker and helper. No service prerequisite, UI-only package, user provisioning script or hidden orphan services. A downloader yielding separately managed products does not meet the architecture's single-product contract.
5. Implement bounded installer transactions: preflight identities/ACLs/IPC/backend, protected durable journal, preserve original W32Time state, quiesce/cancel attributable transient work under current ownership, hand over once, and restore only product-owned changes. Required rollback disabled blocks takeover before mutation. Custom actions need correct install/upgrade/repair/uninstall conditions and paired rollback; validate properties/transforms and exact successor ownership. Ordinary-user repair is still privileged input.
6. Inject failures at meaningful reached stages and reboot interruptions. Separate package publication, installed state, journal progress and acknowledgement. On upgrade do not briefly restore W32Time through old-product removal; on uninstall respect later administrator/GPO changes. Neither NTS outage nor MSI convenience permits an automatic weak-authentication clock controller fallback.
7. Signing and release trust require the actual approved provider/identity, protected authorization, verification and incident/rotation policy. A checksum alone is not independent release authentication. A proposed free-signing route or green unsigned build is not signing acceptance. Do not implement a bespoke privileged auto-updater from the retained TUF assessment.

Coordinate [qa-package-artifacts](../../testing/qa-package-artifacts/SKILL.md), [qa-fault-recovery](../../testing/qa-fault-recovery/SKILL.md) and [qa-final-qualification](../../testing/qa-final-qualification/SKILL.md) for affected claims. Return source/artifact identity, checks actually run, lifecycle/restoration observations, signing status and remaining release blockers separately. Publication and install permission are not granted by readiness.
