# Find missing behavioral evidence

Read [the testing contract](../CONTRACT.md).

Create or resume one requirement/boundary inventory from canonical architecture and current producers/consumers. Record behavior, owner, existing evidence, environment, last assessed identity, missing risk and next discriminating technique. A documentation requirement has no runtime pass until observed.

Include scoped source outside familiar import graphs or known registrations; unexplained roots remain unassessed rather than silently excluded. Distinguish unknown, missing, partial, stale and adequate evidence so an old or narrowly selected pass cannot erase the remaining obligation.

Compare neglected boundaries before revisiting familiar code. Prioritize protected effects, exact arithmetic, strict admission, NTS recovery, authority budgets, persistent recovery, package lifecycle and native UI gaps by reachable impact and uncertainty. Missing tests establish a gap, not a demonstrated product defect.

Select bounded complementary batches and assign cross-worker seams. Record what additional evidence each batch supplies; reconcile actual outcomes and unresolved coverage in the same inventory. Counts, labels and technique-per-file quotas cannot establish semantic completeness.

Preserve the security coverage/critical-file mutation requirements and uninstrumented Windows paths. Use [test planning](../qa-test-planning/SKILL.md) for selected items, then observed results to update the inventory. A local understood change needs no new system workbook.
