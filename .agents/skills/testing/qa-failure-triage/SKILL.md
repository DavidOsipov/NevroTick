# Diagnose verification failures

Read [the testing contract](../CONTRACT.md).

Preserve the first failing native output and exact source/configuration/fixture/runner identity. Determine whether the intended test was selected, reached the operation and failed on the claimed assertion. Listing, unresolved import, earlier parser rejection and generic timeout may answer a different question.

Separate product defect, incorrect expectation, fixture/harness fault, environment/capability gap, policy conflict and unresolved cause. Test competing explanations with the smallest discriminating run or source trace. Reproduce with a healthy neighbor and check indirect consumers/recovery before proposing repair.

For an unexplained effect across boundaries, a smaller witness or a historical introduction question, use [failure localization](../references/failure-localization.md). Trace actual predecessor values/state before choosing a repair. Preserve the same reached semantic failure and healthy control during reduction, including joint order polluters. Historical localization uses real ancestry, faithful revision prerequisites and explicit PASS/TARGET_FAIL/UNRESOLVED outcomes; freshly replay the boundary before drawing a causal conclusion.

Change an oracle only with an independent authoritative reason; matching current output is insufficient. Tests-only tasks retain a valid regression and report the product finding. Authorized repairs use the smallest causal change and unchanged behavioral expectations, then appropriate GREEN evidence.

Retain failed attempts, counterevidence, retries and cleanup failures. A missing native environment remains an evidence gap. Expand scope only when the failure exposes relevant coupling, using [system stabilization](../qa-system-stabilization/SKILL.md) where needed.
