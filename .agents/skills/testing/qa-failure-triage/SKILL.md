# Diagnose verification failures

Read [the testing contract](../CONTRACT.md).

Preserve first failing native output/exact source/configuration/fixture/runner identity. Verify intended test selected/reached operation/failed claimed assertion. Listing/unresolved import/earlier parser rejection/generic timeout may answer different question.

Separate product defect/incorrect expectation/fixture/harness fault/environment/capability gap/policy conflict/unresolved cause. Test competing explanations with smallest discriminating run/source trace. Reproduce beside healthy neighbor; check indirect consumers/recovery before repair proposal.

For native access violations, verifier stops, invalid handles or unexplained
resource growth, use [Windows memory diagnostics](../references/windows-memory.md).
Preserve the first exception/stop, stack, reached API, effective profile and
candidate identity; CDB exit zero does not overrule a captured fault. Separate
missing symbols/startup failures from reached defects, and distinguish allocator
caching or instrumentation overhead from retention using owner/release-event
measurements. Restore the owned profile on every outcome without discarding
failed-run evidence.

For a costly native callback, ownership or cleanup failure whose history is hard
to recover, consider [recorded execution with TTD](../references/windows-memory.md#optional-recorded-execution-with-ttd).
Preserve the intended target token and sensitive traces; recorder availability
or replay alone proves no product fix or complete lifecycle qualification.

For an unexplained effect across boundaries, a smaller witness or a historical introduction question, use [failure localization](../references/failure-localization.md). Trace actual predecessor values/state before choosing a repair. Preserve the same reached semantic failure and healthy control during reduction, including joint order polluters. Historical localization uses real ancestry, faithful revision prerequisites and explicit PASS/TARGET_FAIL/UNRESOLVED outcomes; freshly replay the boundary before drawing a causal conclusion.

Oracle changes need independent authoritative reason; matching current output insufficient. Tests-only: retain valid regression/report product finding. Authorized repair: smallest causal change, unchanged behavioral expectations, appropriate GREEN evidence.

Retain failed attempts/counterevidence/retries/cleanup failures. Missing native environment remains evidence gap. Expand scope only for failure-exposed relevant coupling; use [system stabilization](../qa-system-stabilization/SKILL.md) where needed.
