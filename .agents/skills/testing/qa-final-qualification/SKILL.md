# Qualify the observed candidate

Read [the testing contract](../CONTRACT.md).

Freeze final relevant source/configuration/lockfile/fixtures and built/installed artifact identities. Reconcile selected requirements, actual named execution, all outcomes, first failures/retries, resources and current unresolved findings. Evidence from an earlier candidate needs an explicit unaffected-state argument.

Confirm selected required gates completed at their adequate evidence layer. Compiler/host simulation, actual Windows tokens/IPC/clock/SCM, native UI/AT, package trust/lifecycle and hardware soak establish different claims. Preserve 90% security-module executable-line coverage and 95% per-critical-file mutation gates when the declared implementation/release scope requires them.

For whole-system stabilization or explicit acceptance require direct [black-box inspection](../qa-black-box-acceptance/SKILL.md) of representative actual inputs/outputs on the frozen integrated candidate. Review source-derived claims and independent findings separately from runtime evidence.

Return qualified within declared scope, not ready for confirmed blockers, or incomplete for missing required evidence, with exact remaining action. Required failures/skips/cancellations/timeouts remain incomplete. A skill/documentation-only change needs pack verification, not unimplemented product gates. Do not imply staged readiness, signing, release approval or standard certification unless separately established.
