# Stabilize a bounded system flow

Read [the testing contract](../CONTRACT.md).

Establish one finite acceptance set and repair/time budget for the requested system flow. Map producers, representations, authorities, state/effects and consumers, including persistence/recovery. Reuse adequate current architecture and evidence rather than restarting generic audits.

For coordinated work retain one parent objective and its full selected perimeter across waves. Assign every required obligation to an owner/package and every cross-package seam to an owned integration check. Package success remains provisional until the combined candidate qualifies the required connections; unassigned or unfinished obligations cannot become backlog merely to close the parent early. A bounded local investigation may keep a concise record without creating work packages.

Select missing behavioral items and complementary workers through [coverage-gap analysis](../qa-coverage-gap-analysis/SKILL.md). Before each repair preserve the counterexample, an earlier valid case and plausible cross-boundary interactions. Validate the oracle independently before changing either implementation or verifier.

Classify failures, apply only authorized causal repairs, retain regressions and run the smallest affected integrated checks. Record newly discovered unrelated issues separately with disposition; do not silently expand support or iterate until no speculative concern remains.

For whole-system/data-pipeline stabilization or explicit input-to-output acceptance, freeze the final integrated candidate and execute [black-box acceptance](../qa-black-box-acceptance/SKILL.md), then [final qualification](../qa-final-qualification/SKILL.md). A bounded local investigation closes on its selected checks without automatically acquiring a system acceptance campaign. Close only the declared scope with evidence for every selected required obligation and seam; unavailable required Windows or package evidence stays incomplete.
