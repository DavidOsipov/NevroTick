# Staged-candidate verification

Use only when the task includes staged-tree review or commit preparation. Preserve existing staging and finish within existing authorization. This is a reviewable procedure, not an unattended exporter or permission to commit.

1. Identify repository root, active index, HEAD/baseline and merge/rebase state. Inspect staged versus baseline, working versus index, and untracked inputs separately. Record pre-existing staged paths/modes/blob IDs and authorized hunks. An unborn branch needs an explicit empty-tree baseline; unresolved conflicts block candidate readiness.
2. Select only intended literal paths or reviewed hunks when staging is authorized. Avoid blanket staging, resetting, stashing, cleaning or source checkout for convenience. Review lock/config changes, renames/deletions, generated files and required new fixtures. `git diff --cached --check` checks whitespace/conflict markers, not program correctness.
3. Freeze the **complete** index tree, including unchanged dependencies and staged additions/deletions. Changed-file copying and testing the dirty working directory cannot establish staged-tree behavior. Use a private alternate index and fresh owned destination where the installed Git supports the required procedure; never run index-replacement commands against the user's index. Compare logical entries/tree identity and source custody before/after capture.
4. Inspect actual attributes, clean/smudge filters, encodings, EOL conversion, sparse/split index dependencies, symlinks, gitlinks/submodules and local path dependencies before materialization. A Git archive can omit `export-ignore` paths. Require complete path/mode/content agreement, or explicitly verified permitted transformations, against the frozen tree. Unsupported materialization is a gap, not a reason to reset the source or silently test another candidate.
5. Run gates from the materialized candidate with owned Cargo outputs/caches and reviewed process effects. Git-dependent inventory checks need faithful isolated Git metadata, not inherited source-repository pointers or accidental ancestor discovery. Building an executable in the source checkout can embed source-root paths; changing its working directory does not necessarily retarget it. Do not fabricate history/HEAD for history-dependent checks.
6. Compare relevant source/configuration/fixture bytes before and after checks. Formatting, hooks, code generation or index-changing tools can invalidate the candidate. Reconcile authorized changes and verify the resulting candidate afresh. Before closeout, compare the current logical index/tree and baseline with the validated receipt. Later changes expire readiness; this is not an atomic promise about a future commit.

Keep required histories, filters or unavailable inputs explicit rather than implementing a large ad hoc exporter. A bounded staged review can report source inspection and missing execution honestly. Provide selection/custody, complete candidate identity, exact commands/environment, results/first failures and remaining readiness limits. Commit, push and publication remain separate authorized actions.
