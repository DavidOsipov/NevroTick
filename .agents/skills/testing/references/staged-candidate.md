# Staged-candidate verification

Use only for staged-tree review/commit preparation. Preserve existing staging/authorization. Reviewable procedure; no unattended exporter or commit permission.

1. Identify repository root/active index/HEAD/baseline/merge/rebase state. Separately inspect staged versus baseline, working versus index, untracked inputs. Record existing staged paths/modes/blob IDs/authorized hunks. Unborn branch needs explicit empty-tree baseline; unresolved conflicts block readiness.
2. When staging authorized, select only intended literal paths/reviewed hunks. No convenient blanket staging/reset/stash/clean/source checkout. Review lock/config changes, renames/deletions, generated files, required new fixtures. `git diff --cached --check`: whitespace/conflict markers, no program-correctness proof.
3. Freeze **complete** index tree: unchanged dependencies, staged additions/deletions. Changed-file copying/dirty-working-directory tests cannot establish staged-tree behavior. Use private alternate index/fresh owned destination where installed Git supports procedure; never replace user index. Compare logical entries/tree identity/source custody before/after capture.
4. Inspect actual attributes, clean/smudge filters, encodings, EOL conversion, sparse/split index dependencies, symlinks, gitlinks/submodules and local path dependencies before materialization. A Git archive can omit `export-ignore` paths. Require complete path/mode/content agreement, or explicitly verified permitted transformations, against the frozen tree. Unsupported materialization is a gap, not a reason to reset the source or silently test another candidate.
5. Run gates from the materialized candidate with owned Cargo outputs/caches and reviewed process effects. Git-dependent inventory checks need faithful isolated Git metadata, not inherited source-repository pointers or accidental ancestor discovery. Building an executable in the source checkout can embed source-root paths; changing its working directory does not necessarily retarget it. Do not fabricate history/HEAD for history-dependent checks.
6. Compare relevant source/configuration/fixture bytes before and after checks. Formatting, hooks, code generation or index-changing tools can invalidate the candidate. Reconcile authorized changes and verify the resulting candidate afresh. Before closeout, compare the current logical index/tree and baseline with the validated receipt. Later changes expire readiness; this is not an atomic promise about a future commit.

Keep required histories/filters/unavailable inputs explicit; no large ad hoc exporter. Bounded staged review may report source inspection/missing execution. Provide selection/custody, complete candidate identity, exact commands/environment, results/first failures, remaining readiness limits. Commit/push/publication remain separately authorized.
