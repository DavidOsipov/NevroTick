# NevroTick v0.2 — проверка дизайн-прототипа

**Дата:** 28 октября 2026 года.  
**Объект:** браузерный дизайн-прототип интерфейса NevroTick v1, версия макета 0.2.  
**Основа:** [RWTC-ARCH-001 revision 1.4](../references/source-docs/windows-time-architecture.md) и [RWTC-FEATURES-001 revision 1.0](../references/source-docs/windows-time-features.md).  
**Результат:** **PASS в перечисленном ниже объёме проверок макета.** Это не приёмка нативного приложения, служб, источников времени или защитных механизмов.

Четыре указанных JPG дополнительно открыты и просмотрены при составлении этого отчёта.

## 2. Подтверждённые браузерные сценарии v0.2

| Выполненное действие | Наблюдавшийся результат |
| --- | --- |
| Повторный **Sync now** при нормальном состоянии | Сохраняются текущая квалифицированная оценка и её возраст; повтор получает **Already checking**, а не новую фиктивную оценку |
| Добавление `custom-time.example` → Review → Apply → Sources | После успешного исхода макета показаны **5 Waiting, 0 Draft**; неприменённого черновика больше нет |
| Изменение источника при `status-stale` → Review | **Apply** заблокирован с причиной **Current service status required**; недоступная связь не превращается в подтверждённый успех |
| Подтверждённая остановка службы → Diagnostics | Раздельно показаны причина, последствия и маршрут **Review repair** для полного пакета |
| **Copy summary** | Копирование в фактический буфер обмена браузерной среды завершилось успешно |
| Начальные настройки Appearance | Выбрано **Use Windows setting**; tray выключен; запуск tray при входе недоступен |
| Включение tray и запуска при входе, затем отключение tray | Зависимый флаг запуска при входе сбрасывается и становится недоступным |
| Tracking после восстановления через двух helpers | Status, Diagnostics и Source details сохраняют происхождение сертификатной даты; исходная plain-NTP подсказка не объявляется аутентифицированной |
| Expired → Diagnostics | Нет сообщения о нормальной работе или соответствии текущей оценки политике; непригодность оценки объясняется явно |
| Текущее `status-recovery` → настройки Recovery | Действующая примерная политика включена и содержит двух helpers; состояние не противоречит показанному использованию подсказок |
| **Sync now** при ограничении частоты | Сохраняются текущая оценка и её возраст; показано ограничение запроса |
| Conflict → меню tray → **Sync now** | Возврат на Status с ожиданием достаточного согласия; действие не открывает Sources вместо запроса |

Подтверждение административных действий здесь имитируется исходом сценария. Настоящий UAC и обращение к привилегированному компоненту не выполнялись. Работа Copy summary с браузерным буфером обмена не квалифицирует будущую нативную реализацию этой функции.

Предпросмотр диагностического экспорта и сохраняемые данные используют один объект `reportContent`; это проверено чтением UI-кода. Фактическая загрузка и последующая независимая проверка экспортированного файла не заявляются как выполненный браузерный сценарий этой версии.

## 3. Автоматические проверки

Команды выполняются из каталога `prototype`:

```bash
npm run build
node tests/input-contract.test.mjs
node tests/presentation-contract.test.mjs
```

### 3.1 Контракт ввода — 13 проверок

Файл: [input-contract.test.mjs](tests/input-contract.test.mjs).

Проверены канонизация hostname/IDN/IPv6; отклонение URL-компонентов, неоднозначного `host:port` и legacy IPv4; границы и формат портов; дублирование канонической идентичности; совместимость профиля и набора источников; сохранение примерного минимума источников; требования к одному/двум helpers; независимость редактора Recovery от сохранённого черновика; полный обзор изменений адреса, протокола, порта, имени, группы, шкалы времени и параметров Recovery.

Эти тесты проверяют локальный контракт формы. Они не устанавливают доступность endpoint, независимость операторов, допустимость сетевого назначения, доверие сертификату или подлинность времени.

### 3.2 Контракт представления — 13 проверок

Файл: [presentation-contract.test.mjs](tests/presentation-contract.test.mjs).

| Группа | Проверенная граница |
| --- | --- |
| Health | Потеря status connection оставляет здоровье службы неизвестным; подтверждённая остановка имеет отдельное основание |
| Freshness | Reply, qualified estimate, applied correction и snapshot имеют отдельные значения возраста; отвергнутый свежий reply не обновляет оценку |
| Generation | После изменения поколения прежний возраст может быть unknown; старые данные не превращаются в свежие |
| Recovery | Успешные one-helper и two-helper примеры сохраняют неаутентифицированное основание; текущая незавершённая процедура имеет `completed: false` |
| Observe и ownership | Режим наблюдения и известный владелец часов независимы; переключатель не означает автоматического возврата Windows Time |
| Копии fixtures | Изменение результата представления не портит исходные источники, evidence, health или retained history |
| Refresh | Checking, Already checking, waiting, rate limit, correction in progress, blocked и unavailable различимы; функция не меняет runtime state и evidence |
| Отдельное разрешение коррекции | Запрос новых измерений не выдаёт разрешение и не подтверждает применение исключительной коррекции |
| Agreement | Пример двух групп по два источника не объявляет majority только из-за выполнения минимума двух |
| Совместимость UI | Сохраняются внутренние роли; пользовательские Main/Supporting/Not used/Draft/Waiting и короткие подписи аутентификации сопоставлены явно |
| Каталог | Новые сцены доступны; observe, rate limit и gradual correction не подменяют Tracking отдельным состоянием доверия |

Функции модели используют демонстрационные данные. Здесь не реализуются второй алгоритм выбора источников, настоящий rate limiter или подтверждение UTC.

## 5. Исправления после review интеграции

| Найденное расхождение | Исправленное поведение и подтверждение |
| --- | --- |
| Diagnostics использовал healthy fallback для Expired и других неохваченных состояний | Нормальная работа не выводится из общего fallback; Expired отдельно проверен в браузере, результат сохранён на снимке диагностики |
| После Apply принятые источники оставались с ролью Draft и текстом о неприменённых изменениях | Активные источники переходят в Waiting; проверенный сценарий дал 5 Waiting, 0 Draft и отсутствие dirty |
| Apply мог объявить новый Acquiring snapshot при недоступном status channel | Для изменения требуется текущий статус службы; в stale-сценарии Apply недоступен с понятной причиной |
| В текущем recovery использовались helpers при показанной выключенной политике | Пример действующей политики согласован с текущим recovery: включён режим двух helpers; проверено в браузере |

Дополнительно v0.2 разделяет health и connection, сохраняет четыре значения свежести, показывает retained recovery после Tracking, отличает завершённую процедуру от текущей и использует отдельный feedback-контракт Sync now. Изменения не добавляют сетевую или привилегированную реализацию.

## 7. Границы PASS и оставшиеся проверки

В указанном объёме подтверждены сборка, два набора контрактных тестов, перечисленные браузерные действия и просмотр четырёх изображений. Отчёт не утверждает, что выполнены все 43 сценария, все переходы или все сочетания профиля, связи, прав, источников и владения.

Не реализованы и не квалифицированы этим результатом:

- нативные Win32-контролы, UI Automation, Narrator, полный keyboard-only маршрут, контрастные темы Windows, DPI и многомониторное масштабирование;
- реальные службы, IPC, broker, полномочия, clock ownership и фактическое изменение Windows time;
- NTP/NTS, TLS/verifier, допуск провайдеров, численный алгоритм выбора/дисциплины и реальная точность UTC;
- настоящий UAC, MSI, подпись, update/repair/uninstall и восстановление Windows Time;
- устойчивость после сна/сбоев, монотонное время, бюджеты коррекции, длительная работа и измерение ресурсов;
- продуктовые security acceptance checks, ASVS-conformity и готовность к выпуску.

**Автономный HTML и упаковка:** браузерные сценарии v0.2 проверялись через живое HTTP-превью. При проверке предыдущей версии навигация `file://` была запрещена политикой среды; в v0.2 этот способ запуска не повторялся и ограничение не обходилось. Открытие автономного HTML с диска не считается выполненной проверкой.

После подготовки отчёта основной исполнитель завершил следующие статические проверки комплекта:

| Проверка | Зафиксированный результат |
| --- | --- |
| Автономный HTML | **PASS:** итоговый файл содержит 4 330 470 байт |
| Встроенный JavaScript | Ровно один module script; `node --check` завершился успешно |
| Внешние ресурсы HTML | 0 внешних ресурсов в `script`/`link`/`img`; нет ссылок на невстроенные `./assets` |
| Новый feature-документ | Сохранённая копия побайтно совпадает с предоставленным документом |
| Исходные документы | Проверка SHA-256 девяти исходных файлов пройдена |
| Брендовые изображения | Четыре PNG сохранены без изменения |

| Относительные ссылки комплекта | На момент проверки разрешаются 242 относительные файловые ссылки |

Эти проверки подтверждают структуру и комплектность проверенного снимка файлов. Они не заменяют запуск автономного HTML с диска, проверку поведения в другой браузерной среде или приёмку нативного Windows-приложения.
