# NevroTick v0.4 — Simple / Power user

**Интерактивный дизайн-прототип для David Osipov · 5 ноября 2026 года**

## Открыть и посмотреть

Откройте **NevroTick-UI-v0.4.html** в браузере с поддержкой AVIF. CSS, JavaScript и оригинальная графика уже включены. Для осмотра не нужны установка, Node.js, сервер или интернет.

По умолчанию открыт **Simple**. Переключатель **Simple / Power user** находится в шапке приложения. Интерфейс приложения — английский; управление демонстрационными сценами и документация — русские.

Сложные понятия снабжены подсказками со значком **?**. Нажмите значок мышью или касанием либо выберите его клавишей Tab и нажмите Enter или пробел. Escape закрывает открытую подсказку. Важные предупреждения остаются видимыми на самих экранах.

| Simple | Power user |
| --- | --- |
| Три вкладки: Status, Settings, About. | Status, Sources, Statistics, Diagnostics, Settings, About; отдельно Date recovery. |
| Одна карточка: состояние, краткое объяснение, оценка расхождения, неопределённость и последний подтверждённый time check. | Краткая сводка Status с действиями; подробные источники, график в Statistics, история и технический контекст в Diagnostics. |
| При проблеме — понятное последствие и следующий шаг. | Полная диагностика и причины исключения отдельных источников. |
| Настройка Time check interval и сводки Date recovery / Background service. | Те же сведения плюс подробная политика, управление службами, свидетельства Roughtime и личные предпочтения. |

Смена режима сохраняет данные сценария, черновики источников, фильтры и выбор частоты. Если выйти из страницы, доступной только в Power user, Simple откроет Status; возврат в Power восстановит предыдущую страницу. Общие вкладки Status, Settings и About остаются открытыми.

## Трей и выход из приложения

Под окном расположен отдельный образец области уведомлений Windows. По умолчанию
трей выключен. Включите его в **Settings → Tray and sign-in** (Simple),
**Settings → Your preferences** (Power user) или кнопкой «Включить пример трея»
на панели проверяющего. Все эти изменения остаются в памяти HTML.

Значок показывает текущее состояние и подсказку; щелчок или контекстное меню
открывает **Open NevroTick**, **Sync now / Check sources**, **Diagnostics**,
**Settings**, **About NevroTick** и **Quit UI**. Стрелки и Home/End выбирают пункт;
Escape закрывает меню и возвращает фокус. Меню не запускает проверку времени при
открытии. Контрастность и размеры 16/20/24 px доступны для осмотра отдельно.

**Quit UI** сначала предупреждает, что работающие службы продолжат работу.
Остановленное или неизвестное состояние обозначается явно. **Manage background
service** открывает **Settings → Background service** и оставляет наблюдатель
активным: **Stop** предназначен для временной остановки, **Disable NevroTick** —
для запрета будущего запуска. Они требуют своих отдельных подтверждений.
**Keep NevroTick open** отменяет выход, **Quit UI only** закрывает только пример
наблюдателя. Его значок и новые локальные уведомления исчезают; настройки трея,
входа, служб и владелец часов не меняются. Кнопка на внешней панели вновь открывает
пример. Настоящее приложение, процессы и службы Windows здесь не вызываются.

## Управление фоновыми службами и временем

**Power user → Settings → Background service**. В Simple Settings есть сводка и ссылка **Manage service in Power user**. Управление относится к согласованной паре NevroTick: движку измерений и контроллеру часов.

| Элемент | Действие |
| --- | --- |
| **Start / Stop / Restart** | Изменяют текущую работу пары. Stop временный и не меняет автозапуск. |
| **Diagnose** | Открывает диагностику без административного изменения служб. |
| **Start automatically with Windows** | Включает или выключает будущий автоматический запуск обеих служб. Off означает Manual, не останавливает их; On не запускает остановленные службы. |
| **Disable NevroTick** | Останавливает обе службы, запрещает их запуск и recovery-restart, подтверждает завершение принадлежащего NevroTick управления часами. Сохраняет настройки и историю. Windows Time автоматически не включается. |
| **Use Windows Time** | Явно передаёт управление Windows Time: проверка готовности, прекращение работы NevroTick и освобождение часов, запрет его запуска, включение/запуск W32Time по разрешённой конфигурации, отдельная проверка владельца. |
| **Use NevroTick** | Явный обратный переход. W32Time останавливается и его запуск запрещается с сохранением настроек для будущего возврата; NevroTick начинает новую проверку времени. |

Изменения требуют административного разрешения в настоящей программе; макет показывает подтверждение и тестовый ответ. Для отключённой пары **Enable and start** явно включает Manual и запускает её на текущий сеанс, оставляя автозапуск Off. При владельце Windows Time обычный Start или автозапуск NevroTick включает только наблюдение и не перехватывает часы.

В макете после подтверждения запрос остаётся **Pending**. Внешняя панель **Сценарии макета → Тестовые ответы** управляет ответами:

- Для Start/Stop/Restart: **Ответ управления службами · образец → Deliver sample service response**.
- Для автозапуска, полного отключения и передачи: **Автозапуск и владение · ответ → Deliver sample lifecycle response**.
- Перед передачей **Готовность передачи · образец** позволяет проверить разрешённую организационную политику, конфликт политики, недоступную зависимость или неподтверждённого владельца. Это условия проверки, а не настройки внутри приложения.

Есть подтверждённый результат, отмена разрешения, отказ до выполнения, неизвестный и частичный исход. Открытие других экранов сохраняет pending-запрос; сброс сцены предупреждает о его потере. Неизвестный исход не объявляется успехом и блокирует слепой повтор. Неподтверждённое освобождение часов не считается полным отключением и не разрешает запуск второго контроллера.

W32Time не переводится безусловно в Automatic: для него допустим Manual/trigger-start. Реальные зависимости следует читать из конфигурации конкретной Windows; фиксированного списка дополнительных служб в макете нет. Доменная политика, серверы, провайдеры и триггеры Windows должны сохраняться. В примере готовности дополнительных изменений служб не требуется — это демонстрационное условие, не утверждение обо всех компьютерах.

Состояние служб, конфигурация запуска, владелец часов и подтверждённая синхронизация показаны отдельно. Работающий W32Time не означает проверенную синхронизацию. После передачи настройки источников, профиля и интервала NevroTick остаются сохранёнными и явно относятся только к NevroTick; прежние NTS/Roughtime-данные остаются историей. Start/Restart и передача не создают измерений, голосов, аутентификации или разрешения коррекции.

Изменение только автозапуска сохраняет текущую синхронизацию и временную диагностику. Подтверждённая Stop/Restart завершает служебный компонент диагностики; компонент окна независим. Отмена и отказ до выполнения сохраняют прежние наблюдения. Подробности и официальные источники: [отчёт об управлении временем](review/time-management/REPORT-RU.md).

## Уведомления Windows о проблемах

**Settings → Notifications** в Power user; в Simple Settings — тот же переключатель и переход к подробностям. **Notify me about problems** включает уведомления о важных проблемах и необходимых действиях. Повторные наблюдения одного инцидента не создают новые всплывающие сообщения. Обычные успешные проверки, постепенная коррекция, выбранный observe-only/NTP и запрошенная остановка не считаются поломкой.

Для локальных предупреждений подходят **Windows app/toast notifications**. Облачный WNS — push от сервера; новый сервер, push-канал или фоновая служба для этого макета не добавляются. В настоящей программе локальное уведомление должен показывать работающий пользовательский интерфейс или наблюдатель в трее. Закрытие последнего такого процесса прекращает возможность отправлять новые предупреждения; работа служб синхронизации от этого не прекращается.

Переключатель приложения отделён от разрешений Windows. Системные настройки, Do Not Disturb, организационная политика или отсутствие работающего наблюдателя могут препятствовать показу. Проблема остаётся видна внутри NevroTick. Макет не заявляет фактическую доставку, прочтение или подтверждённую синхронизацию после тестового сообщения.

**Send test notification** показывает безопасный образец и соблюдает переключатель приложения и выбранную готовность Windows. Переход к настройкам Windows в HTML объясняет будущий переход, не запускает системную команду. Показанный снаружи окна **Windows notification preview** — часть макета, а не настоящее окно ОС.

Тестовые условия находятся в русской внешней панели сценариев: она публикует текущий образец статуса, признак затянувшейся проблемы, доступность Windows и пользовательского наблюдателя. Таймеров и настоящего мониторинга нет. Для мягкой деградации нужен опубликованный признак persistent/actionable, а не условное число опросов. Смена целой сцены создаёт независимый набор наблюдений и не доказывает устранение прежней проблемы.

Нажатие уведомления открывает текущий статус/контекст и заново проверяет актуальность. Оно не одобряет коррекцию, не повторяет неизвестную операцию и не меняет службы. Текст не содержит приватных адресов источников или диагностического содержимого. Закрытие карточки убирает её показ, сохраняя саму проблему и подавление повторов.

Политика всех статусов, результаты аудита и официальные источники — в [отчёте](review/status-notifications/REPORT-RU.md).

## Roughtime в первой версии

По решению владельца от 5 ноября 2026 года Roughtime включён в предполагаемый состав v1. В макете это автоматическое восстановление приблизительной даты, когда пригодной основы для проверки NTS нет. Если сохранённый или строгий NTS уже пригоден, ожидать Roughtime не требуется.

В **Simple → Settings** доступна сводка Date recovery с переходом к подробностям в Power user. В **Power → Sources** источники восстановления показаны отдельно от источников обычной синхронизации; их свидетельства и история доступны на **Date recovery** и **Diagnostics**. Roughtime не получает обычных NTS-голосов и сам не меняет Windows-время.

В макете 30 сцен. Сцены Roughtime показывают проверку подписанной даты, передачу пригодного интервала NTS, успешное NTS-восстановление с сохранённым происхождением даты, недоступность, отклонённую подпись и конфликт подписанных данных. Имена `.example`, ключевые идентичности и интервалы — демонстрационные; они не выбирают production-провайдеров или доверенные ключи. Автоматический резерв через NTP остаётся отдельным будущим сценарием. Ранее сохранённая сцена `recovered` по-прежнему означает восстановление через неаутентифицированный NTP; успех Roughtime представлен отдельной сценой.

## Частота проверок времени

**Settings → Time check interval**:

- **Automatic (recommended)** — исходный выбор макета.
- **Custom → Every 2 / 5 / 15 minutes** — предложенные интервалы проверки; **Enter my own interval** — целое число минут от 1, введённое пользователем.
- **Update preview** сохраняет выбор в памяти страницы; **Cancel** отменяет несохранённый выбор.

Эта настройка задаёт частоту запросов измерений. Она не означает обязательный перевод системных часов каждые N минут. Восстановление соединения и ограничения сервера могут изменить фактический интервал. Пользовательское число хранится только в макете; пустой ввод, ноль, отрицательные и дробные значения не сохраняются. Пресеты 2/5/15 минут предложены для обсуждения дизайна; они не объявлены утверждёнными production-пределами.

Выбор частоты не меняет фиксированный тайминг демонстрационного сценария. Настройка сохраняется при переключении режимов и сцен; явный полный сброс или перезагрузка страницы возвращает Automatic.

## Маршрут осмотра на несколько минут

1. Посмотрите начальный **Simple → Status**. Здесь нет таблиц источников, журнала и дополнительных информационных карточек.
2. Откройте **Settings**, выберите **Custom → Every 5 minutes → Update preview**.
3. В шапке переключитесь в **Power user**. Та же настройка сохранена. Откройте **Statistics**: видны интервалы источников, точные числа, аутентификация, согласие и разные возраста данных.
4. Откройте **Sources → Add source preview**. Пример: `Epsilon` / `epsilon.example` / `NTS` / `4460`. Сохраните черновик, переключитесь в Simple, затем обратно. Черновик остаётся черновиком, измерения не меняются.
5. Разверните **Сценарии макета** над окном. Сравните потерю связи со статусом, подтверждённую остановку службы, конфликт источников, неаутентифицированный NTP и неизвестный результат изменения часов.
6. В проблемной сцене Simple нажмите **What can I do?** и выберите предложенный переход в Power user. Для конфликта владения часами доступен **Time policy**.

Сохранены предыдущие сценарии, включая три сцены ограничения запросов: RATE отдельного источника, DENY и отложенные запросы ко всем источникам. В этой итерации добавлены отдельные состояния Roughtime: пригодная дата передана NTS, успешное NTS-восстановление через Roughtime, недоступность и отклонённая подпись. Смена сцены или полный сброс предупреждают о потере локальных черновиков. Полный сброс возвращает начальные данные и частоту Automatic, сохраняя выбранный режим представления. Смена только сценария сохраняет частоту и режим, но очищает старые черновики, контекст возврата и демонстрационную сессию диагностики.

## Дополненные сценарии для осмотра

- **Settings → Time policy → Change profile preview:** выберите NTS, NTP или observe-only, затем посмотрите сравнение и последствия. Настройка остаётся черновиком в макете.
- **Time policy** или **Sources → Explore recovery → Configure helper preview:** выберите 0, 1 или 2 помощников и посмотрите предупреждения и обзор. При двух нужны обе различные идентичности.
- **Status → Sync now:** ответ появляется рядом с кнопкой. Выбор тестового результата находится в русской панели сценариев вне окна приложения и ограничен совместимыми со сценой ответами. Действительный запрос не отправляется.
- **Diagnostics → Preview temporary collection:** пользователь выбирает область и длительность; отдельные результаты UI/службы задаются в панели сценариев. Start и Stop работают только в макете. Неизвестный ответ не объявляется подтверждённым отказом или остановкой.
- **Date recovery → Back:** возвращает к месту входа с прежними фильтрами, прокруткой и фокусом. Вход из Simple заранее обозначает переход в Power user; возврат восстанавливает Simple. При уходе из изменённого редактора помощников можно сохранить черновик, отбросить правки или продолжить редактирование. Незавершённый сохранённый черновик проходит проверку перед Review.
- **Settings → Your preferences:** включите образцы опций трея и запуска при входе и откройте пример меню трея. Процессы и службы Windows не меняются.
- **Подтверждённая остановка службы → Diagnostics:** инструкции по восстановлению и просмотр диагностического отчёта находятся рядом с проблемой. В Settings доступны Synchronization, Time policy, Your preferences и Background service.

В Power user Status показывает состояние, оценку, доверие, согласие и действия на одном экране. В Diagnostics сохранены отдельные возраста данных, история восстановления и журнал; Statistics открывается с графика сравнения. При конфликте **Compare sources** ведёт непосредственно к графику. Примеры Sync now учитывают текущую сцену.

**About** описывает проект NevroTick, автора, платформу и GitHub-репозиторий. Разделы Technologies and libraries и License and artwork содержат сведения о происхождении алгоритмов, текущих зависимостях и лицензиях.

## Что работает в прототипе

Переключение режима и страниц, выбор сцен, частота проверок и отмена изменений, поиск/фильтры источников, локальное добавление и редактирование черновиков, просмотр предложенной коррекции, чтение и локальное сохранение демонстрационной диагностической сводки.

Это образцы данных. **Sync now, Start, Stop, Restart, автозапуск, Disable NevroTick, Use Windows Time, Use NevroTick, Apply changes и Approve once не выполняют системных действий.** Прототип не обращается к NTP/NTS/DNS, службам Windows или UAC и не меняет часы. Настройки находятся в памяти открытой страницы; перезагрузка их сбрасывает.

## Проверка и ограничения

Для обновлённого макета выполнены 197 тестов модели и представлений, структурная проверка 1 247 вариантов HTML, проверка CSP-hash автономного файла и оригинальных AVIF. Проверены оба варианта HTML в Chromium, в том числе статусы, управление запуском и временем, уведомления, состояния pending/unknown/partial, история, диагностика, возврат фокуса и компоновка на 360/1280 px. Независимый проход дополнительно проверил 480 px. Результаты текущей итерации и её ограничения описаны в `review/status-notifications/REPORT-RU.md`; другие сохранённые результаты в `review/` относятся к прежним версиям.

В облачном Chromium прямые `file://`-адреса запрещены административной политикой, поэтому визуальные и интерактивные проверки выполнялись через локальный HTTP-сервер. Автономный HTML включает стили, код и изображения; внешних зависимостей при структурной проверке нет.

Это ограниченная проверка HTML-прототипа: она не подтверждает работу службы, нативную доступность Windows, полную поддержку технологий чтения с экрана или все возможности браузера. Нативная проверка и принятие интерфейса владельцем остаются отдельными шагами.
