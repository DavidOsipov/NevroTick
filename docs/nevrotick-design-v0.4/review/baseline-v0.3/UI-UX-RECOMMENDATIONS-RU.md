# NevroTick v0.3 — рекомендации и результат переработки UI/UX

**Дата:** 5 ноября 2026 года. **Владелец:** David Osipov.

**Основа анализа:** commit `8a66af924c509e898a9bab9bb3282f11b24fba93` репозитория `DavidOsipov/NevroTick`. Анализ выполнен по текущим документам, исходникам v0.2 и двум историческим снимкам интерфейса. Новая версия реализована как отдельный автономный дизайн-прототип.

## Главный вывод

У v0.2 уже была разумная основа: компактная утилита, вкладки Status / Sources / Settings, раздельные аутентификация и согласие, понятные роли Main / Supporting / Not used. Поэтому задача состояла в сохранении этой основы и согласовании интерфейса с новой архитектурой, включая честные состояния ошибок и восстановления. Полная замена визуального языка или перевод продукта на веб-стек не требовались.

Наиболее существенный разрыв оказался между текстовой спецификацией и реально отображаемыми fixtures. В документах уже появились новые правила leap seconds, MSIX и будущего Roughtime-восстановления; старые сцены и некоторые тексты этого ещё не отражали. Дополнительно найден внутренне противоречивый сценарий большой коррекции: предложение `+372 s` сочеталось с серверными измерениями около `−0.7 ms`.

Канонические основания: [руководство по документации](https://github.com/DavidOsipov/NevroTick/blob/8a66af924c509e898a9bab9bb3282f11b24fba93/docs/README.md), [архитектура](https://github.com/DavidOsipov/NevroTick/blob/8a66af924c509e898a9bab9bb3282f11b24fba93/docs/windows-time-architecture.md), [feature-план](https://github.com/DavidOsipov/NevroTick/blob/8a66af924c509e898a9bab9bb3282f11b24fba93/docs/windows-time-features.md), [решения владельца](https://github.com/DavidOsipov/NevroTick/blob/8a66af924c509e898a9bab9bb3282f11b24fba93/docs/nevrotick-owner-decisions.md).

## Как распределён анализ

Два независимых субагента подготовили рекомендации: один — по архитектуре, доверительной модели и актуальным требованиям; второй — по пользовательским сценариям, формам, информационной структуре и ясности состояний. В комплект включены их исходные отчёты: 14 архитектурных рекомендаций и 11 UX-рекомендаций. Координатор объединил их, изучил исторические снимки и графику, реализовал v0.3 и устранил замечания повторной проверки.

Это анализ исходников и предложенного опыта использования. Его нельзя называть полноценным наблюдением пользователей или свежим визуальным аудитом работающего интерфейса: новый HTML не удалось открыть в облачном браузере из-за политики доступа к локальным файлам/серверу.

## Что сохранено из v0.2

Сохранены английский язык приложения, русские инструкции для владельца, исходный взрослый персонаж, serif wordmark, системный UI-шрифт, спокойные нейтральные поверхности и компактная утилитарная структура. Main / Supporting / Not used / Waiting остались ролями источников, Draft — отдельной меткой изменений. Offset и uncertainty остаются рядом, знак offset объясняется словами.

Внешний фон стал теплее и согласован с AVIF-набором. Основные рабочие поверхности оставлены светлыми, с одним сине-серым акцентом. Статус дополнен текстом, поэтому смысл не зависит только от цвета. Основной текст таблиц и статуса поднят минимум до 12 px, вторичный — обычно до 11 px; это решение макета, а не заявление о пройденной native DPI/accessibility qualification.

Из браузерного образца удалены имитации системных кнопок Minimize/Close: старый прототип путал минимизацию с закрытием. Настоящее поведение окна принадлежит будущему native UI и текущим UI-M0-наблюдениям.

## Сценарии v0.3

| Группа | Сцены |
| --- | --- |
| Ежедневная работа | Нормальная синхронизация; первый сбор; holdover; истёкшая оценка; отсутствие ответов; конфликт источников; stale connection; подтверждённая остановка службы; конфликт владельца; resume; observe-only; явный NTP; плавная коррекция. |
| Календарь UTC | Неизвестный будущий leap-календарь; проверка вокруг UTC-перехода. |
| Будущее восстановление | Roughtime; условный unauthenticated reserve; NTS после reserve; подписанный конфликт. |
| Защищённые действия | Большая коррекция; истёкшее предложение; неизвестный исход операции. |
| Поддержка | Частичный сбор диагностических данных. |

Шесть экранов: Status, Sources, Diagnostics, Settings, Date recovery и About. Основная навигация содержит четыре вкладки; восстановление и About доступны отдельно. Сцены выбираются снаружи приложения, а не «успешным» выполнением защищённых кнопок.

## Исправления по независимой проверке нового кода

Повторный анализ оказался полезен: общий healthy-fixture позволял случайно унаследовать неподходящие подписи. Исправлены NTS certificate basis в NTP-профиле, свежие ages после resume, текущие source ages в stale snapshot, 3/4 agreement у истёкшего предложения, authentication note при signed conflict и активный service logging при недоступной службе.

Отдельно разделены **историческая общая оценка** и **текущие спорные ответы источников**. В конфликте источники по-прежнему могут иметь текущую NTS-аутентификацию, хотя их время не образует пригодного согласия. Это не тот же случай, что потеря связи с UI.

Дополнительно исправлены некорректное принятие IPv6 с одиночными двоеточиями на краях, видимость name-only изменений в Review, редактирование уже добавленного черновика и восстановление HTML-фокуса после перерисовки фильтров/настроек. Реальное фокусное поведение браузера ещё требует наблюдения.

Исходные отчёты агентов в `review/` сохраняют историю находок и проверенный ими момент времени. Заключительные две узкие правки архитектурного отчёта — разделение истории источников/оценки и отсутствие ложной healthy-NTS стадии в reference-view — внесены после его последней записи и покрыты отдельным тестом координатора. Последнее небольшое замечание UX-отчёта про display name также исправлено и покрыто тестом.

**Не выполнено:** новый HTML не был открыт и проверен в настоящем браузере, потому что облачный браузер блокирует локальный адрес и file-протокол. Поэтому не заявляются визуальная приёмка, отсутствие переполнений на всех размерах, проверенные клики, dialog/focus behavior, работа clipboard/download в браузере пользователя или нативная доступность. Файл предназначен для следующего осмотра David именно как предложение дизайна.

## Границы принятого решения

Не выбраны новые NTS-провайдеры, shipped default profile, точные универсальные пределы больших коррекций, длительность holdover или процент «точности». Числа сцен — согласованные примеры, не новые product defaults. Catalogue scoring, pinning и будущий системный DNS не превращены в уже доступные вкладки.

Подготовка v0.3 не меняет выбранный Rust/Win32-стек, состояние UI-M0, D1/D2/D3, существующие execution holds, формальные доказательства Core или release acceptance. Отдельный HTML не является production UI implementation.

Исходный репозиторий не изменён. Этот комплект — конкретный результат для осмотра и последующего решения о переносе в поддерживаемые документы/реализацию.
