Основа — макет после аудита, SHA-256 автономного HTML: `857a1e712c55bc22e4b500799dafb4dfda19789bce58491068fa2c9038364309`. Проект касается HTML-прототипа и не меняет границы нативного UI-M0.

## 1. Ограничение запросов и отказ конкретного сервера

Рекомендация: две дополнительные фиксированные сцены, без моделирования сетевого планировщика или произвольных производственных таймеров.

| Сцена | Что произошло | Что видит пользователь |
| --- | --- | --- |
| Сервер ограничил частоту запросов | Delta прислал RATE; остальные три источника обеспечивают нужное согласие | Simple сохраняет Time sync active. В Sources видна причина Checks delayed by server у Delta. Пользователь не обязан менять настройки. |
| Сервер отказал в обслуживании | Beta прислал DENY; его прежнее измерение уже непригодно по возрасту, а оставшиеся текущие измерения не обеспечивают действующее правило согласия | Using the last valid estimate, пока прежняя модель пригодна. Действие Review sources ведёт к Beta. Когда пригодной модели нет, применяется существующее No usable time estimate. |

DENY сам по себе не объявляет старое измерение просроченным. Вторая сцена явно задаёт оба факта отдельно. Ни одна сцена не уменьшает требования к согласию и не меняет профиль NTS.

Недостаточность согласия во второй сцене — отдельно заданный результат отбора Agreement not met. Интерфейс не вычисляет его собственной арифметикой по числу оставшихся серверов: точный знаменатель большинства и правила свежести должны прийти из принятой политики и данных службы. Это не универсальное правило «двух серверов всегда недостаточно». См. [границы текущего предложения по согласию](/workspace/NevroTick/docs/windows-time-features.md:105).

В строке источника остаются Main / Supporting / Waiting / Not used и понятная причина. RATE и DENY обозначают состояние запросов, а не новые роли. Пригодность старого измерения, состояние запросов и аутентификация остаются разными сведениями.

В подробностях источника:

- Request status: Checks delayed by server / Access refused by server.
- Last control response: отдельно от Last accepted measurement.
- Control response: RATE / DENY в технических подробностях.
- Next permitted check: только значение, опубликованное службой. В статическом примере без такого значения — Scheduled by the service для RATE и Not established для DENY.

Пояснение RATE: “The server asked NevroTick to send requests less often. Further checks of this source are delayed.”

Пояснение DENY: “The server refused access. Review its usage policy or configuration.”

Общее пояснение в подробностях: “This response contains no time measurement. It does not refresh the last accepted measurement.” Контрольный ответ также не создаёт нового подтверждения аутентифицированного времени.

На Diagnostics — одно понятное событие с идентичностью источника и последствиями; повторяющиеся сообщения объединяются. Действие View affected source открывает Power → Sources, выделяет нужный источник и показывает его подробности. Если прежний фильтр скрывал строку, он очищается с видимым сообщением “Filters cleared to show the affected source”. Переход из Simple заранее называется “Review source in Power user”.

Sync now соблюдает ограничения источников. Если остальные источники можно проверить, проверяются они. Если допустимых запросов сейчас нет, интерфейс объясняет это. DENY не получает обещания “попробуйте через N секунд” без установленного срока. Не добавляются обходные кнопки, автоматическое удаление источника или переход на plain NTP.

Почему этот вариант: одних подсказок недостаточно для проверки последствий; имитация планировщика закрепила бы ещё не утверждённые интервалы и правила повторного включения. Две сцены покрывают локальную проблему при нормальной работе и потерю достаточного текущего согласия.

Основания: [F-02 и F-03](/workspace/NevroTick/docs/windows-time-features.md:79), [F-05](/workspace/NevroTick/docs/windows-time-features.md:126), [архитектура §7.3](/workspace/NevroTick/docs/windows-time-architecture.md:731).

## 2. Возврат из Date recovery

Рекомендация: запоминать один контекст входа на вложенную страницу. Полноценная история маршрутов для этого не нужна. Постоянный возврат на Status теряет контекст пользователя.

При открытии запоминаются исходная страница, подраздел Settings, режим, фильтры/поиск, положение прокрутки и устойчивый ключ элемента, с которого открыта страница. Повторный переход внутри Date recovery не перезаписывает этот контекст.

Названия кнопки соответствуют цели: Back to sources, Back to diagnostics, Back to time policy или Back to status. Не используются Back без понятной цели и возврат к исчезнувшему элементу.

При возврате восстанавливаются фильтры и прокрутка, фокус получает исходная кнопка. При входе из подробностей источника сохраняется его идентичность и восстанавливается соответствующий диалог; если источник больше недоступен, открывается Sources. Если исходный элемент исчез, фокус переходит к заголовку исходной страницы. Если исходного контекста нет, используется Status.

Различаются три состояния: действующие данные сцены, сохранённый локальный preview и ещё не сохранённые изменения формы. При уходе из изменённого редактора предлагаются Keep draft and leave / Discard edits / Stay here. Escape в этом предупреждении означает Stay here; если открыта подсказка, первое Escape закрывает только её. Предупреждение показывается в том же диалоге, а не новым окном поверх него. Отдельное Discard helper preview сбрасывает сохранённый локальный preview. Простое закрытие обзора preview не уничтожает его, а на повторном открытии редактор восстанавливает сохранённые поля.

Keep draft and leave сохраняет введённые поля в памяти страницы, в том числе незавершённый ввод, и закрывает редактор. В интерфейсе видна отметка Helper draft not applied. Для перехода к Review helper preview по-прежнему нужна валидация. Discard edits возвращает прежний локальный preview, если он был, и не меняет действующие данные сцены. Это выполняет требование предупреждать перед уходом из несохранённого черновика без повторных предупреждений при чтении уже сохранённого preview.

Нельзя молча переносить административные изменения из черновика в действующие настройки. Review helper preview показывает только локальный черновик. Переключение режима и возвращение к исходной странице не выполняют никаких действий с часами или службами.

Вход из Simple через помощь заранее называется Review date recovery in Power user. Back восстанавливает исходный Simple и Status. Для входа из Power возвращается исходный Power и его страница. Это временный просмотр подробностей с явным возвратом к исходному режиму.

Обычное переключение режима на время сохраняет контекст восстановления: Recovery → Simple Status → Power возвращает на Recovery. Явный выбор другого экрана завершает этот вложенный маршрут; новый вход создаёт новый контекст. Это согласуется с сохранением последней страницы Power и не должно неожиданно переключать режим после отдельного осознанного перехода. Пока редактор открыт, действуют существующие ограничения переключения режима.

Смена сцены и полный сброс завершают старый контекст. Если они уничтожат черновики, сначала запрашивается подтверждение сброса с возможностью отмены. В новой сцене не остаются несвязанные открытые диалоги или фиктивные сессии старой сцены.

Основания: [предупреждение о несохранённом черновике](/workspace/NevroTick/docs/windows-time-features.md:262). Поведение возврата в исходный режим — моя рекомендация для HTML-макета, а не уже утверждённое правило продукта.

## 3. Действия и демонстрационные исходы

Рекомендация: исход выбирается средствами проверки макета, а внутри окна приложения остаются параметры действия, само действие и его результат. В русской панели Сценарии макета можно явно задать тестовый ответ; его выбор не меняет произвольно состояние часов.

### Sync now

Пользователь нажимает Sync now без диалога выбора результата. Вблизи кнопки появляется компактный ответ с доступным объявлением состояния. Он не вытесняет основной статус и не прячет следующий шаг в обязательном модальном окне.

Ответ команды задан отдельными данными сцены. Из запрета коррекции нельзя автоматически вывести запрет измерений. Успешный приём запроса не означает ни получения пригодного измерения, ни изменения часов.

| Ответ | Смысл и следующий шаг |
| --- | --- |
| Checking | Запрос на измерения принят. Не показывать Synchronised только на основании нажатия. |
| Already checking | Повторное нажатие присоединяется к текущей проверке и не запускает параллельный обход ограничений. |
| Waiting for enough agreeing sources | Ответы ещё не дали нужного согласия; правила не ослабляются. |
| Checks delayed by server limits | Допустимые запросы отложены. Видны причина и данные о следующей возможности, если они известны. |
| Source access refused | Отказ конкретного источника, без обещания окончания запрета; ссылка на него. Другие источники проверяются, если это допустимо. |
| Correction in progress | Действующая коррекция не получает новых полномочий от повторного запроса. |
| Status unknown | Связь с состоянием потеряна; нельзя утверждать, что команда принята или служба остановлена. |
| Check unavailable | Конкретная подтверждённая причина и подходящее действие; не общий тупик “ошибка”. |

В прототипе сохраняются явные пометки Sample data и Sample response. Не изображается реальная отправка запросов, таймер измерения или выполненная коррекция. Базовые ответы воспроизводимы, а дополнительные исходы выбираются в панели сценариев, включая сценарий повторного нажатия. Панель предлагает только согласованные с текущими данными варианты: нельзя отдельно выбрать успешный ответ остановленной службы или достаточное согласие без соответствующих измерений. Для несовместимого примера выбирается целиком другая сцена.

### Временная диагностика

Внутри пользовательского диалога остаются только область сбора, длительность, начало, остановка и действительное состояние каждого выбранного компонента. Выбор Active / Partial / Failed относится к панели сценариев.

По UI-части и службе выводятся отдельные результаты. Partial допустим только если реально запущена часть выбранного объёма. При выборе только Service и отказе в разрешении итог — Not started, а не Partial. Никакое закрытие диалога не выдаётся за остановку служебной работы.

В макете состояние и оставшаяся длительность явно демонстрационные; производственные пределы и срок не выводятся из примеров 5/15/30 минут. Нажатие не имитирует разрешение UAC или фактический сбор данных.

Почему этот вариант: сохранение выбора результата внутри приложения искажает пользовательский поток; удаление всех примеров мешает проверке макета. Панель сценариев сохраняет покрытие примеров, а компактный ответ рядом с действием убирает лишнее модальное окно. Результаты компонентов диагностики задаются сценой отдельно и затем сводятся в общий итог; общий выбор Partial не подменяет фактическое сочетание компонентов.

Основания: [F-05](/workspace/NevroTick/docs/windows-time-features.md:126), [F-09](/workspace/NevroTick/docs/windows-time-features.md:195).

## 4. Проверка следующей версии

1. RATE одного источника не превращает здоровое согласованное состояние в аварию. DENY не обновляет измерение и не получает выдуманного времени окончания.
2. При утрате достаточного согласия показывается удержание прежней модели либо отсутствие пригодной оценки — по данным сцены. Согласие и аутентификация не подменяют друг друга.
3. Sync now не обходит ограничения, не разрешает коррекцию и не обновляет возраст предыдущих измерений одним нажатием.
4. Переходы из Sources, Diagnostics, Settings и Simple возвращают пользователя в предусмотренный контекст; отдельно проверяются фильтры, прокрутка и клавиатурный фокус.
5. Уход из изменённого редактора предлагает сохранить ввод, отменить правки или продолжить редактирование. Escape не уничтожает поля. Уже сохранённый preview переживает обычную навигацию; смена сцены и полный сброс предупреждают о его потере.
6. В окне приложения нет выбора результата команды. Рецензент по-прежнему может проверить все нужные исходы через панель сценариев.
7. Частичный сбор диагностики соответствует выбранным компонентам; отказ в разрешении не выглядит как успешный запуск.
8. Проверяются оба режима, клавиатура, диалоги и ширины 360, 480 и 1280 px. About остаётся доступной в обоих режимах.

Не входит в эту итерацию: реальная сеть, сервисы Windows, управление часами, производственные правила KoD, подтверждение работы скринридера или выдача нативного UI-M0 за готовый продукт.
