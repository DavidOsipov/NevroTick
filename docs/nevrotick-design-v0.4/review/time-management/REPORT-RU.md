# Автозапуск, полное отключение и управление временем

5 ноября 2026 года. Расширение HTML-прототипа по прямому поручению владельца. Настоящее приложение и канонический репозиторий NevroTick не изменяются.

## Что добавлено

В **Power user → Settings → Background service** доступны отдельные действия:

| Управление | Смысл |
| --- | --- |
| Start / Stop / Restart / Diagnose | Текущая работа и диагностика согласованной пары служб. Stop не меняет автозапуск. |
| Start automatically with Windows | Автозапуск обеих служб. Off переводит в Manual, не останавливая текущую работу; On не запускает остановленную пару. |
| Disable NevroTick | Остановка обеих служб, запрет обычного и recovery-запуска, подтверждённое завершение принадлежащего NevroTick управления часами. Настройки и история сохраняются. |
| Use Windows Time | Явная передача управления W32Time после проверки политики, готовности, прекращения работы и подтверждённого освобождения часов. |
| Use NevroTick | Явный обратный переход: остановить и запретить запуск W32Time, сохранив его настройки; подтвердить нового владельца и начать свежую проверку времени. |

В Simple Settings сохранены сводка и прямой переход к управлению. После полного отключения **Enable and start** явно переводит NevroTick в Manual и запускает на текущий сеанс. Автозапуск остаётся Off, пока пользователь отдельно не включит его. При владельце Windows Time обычный Start включает только наблюдение: часы остаются под Windows.

Каждое изменение предваряется планом и объяснением административного разрешения. В макете подтверждение создаёт только запрос в памяти страницы. Условия готовности и тестовый ответ выбираются во внешней русской панели сценариев, отдельно от приложения. Подробнее о кнопках передачи ответа — в [README](../../README-RU.md#управление-фоновыми-службами-и-временем).

## Честное представление результата

Текущая работа, конфигурация будущего запуска, владелец часов и подтверждённая синхронизация — разные наблюдения. Изменение только автозапуска не ухудшает текущую синхронизацию и не прекращает DEBUG-сеанс. Pending/Unknown не изображаются положением переключателя Off. Пока исход неизвестен, слепой повтор изменения недоступен; Diagnose остаётся доступной.

Полное отключение подтверждается только при остановленных службах, запрещённом запуске и подтверждённом завершении их управления часами. Остановленные процессы сами по себе не доказывают освобождения часов. При неопределённом завершении показывается Partial, Windows Time не запускается. Если освобождение подтверждено, но W32Time не стартовал, интерфейс явно сообщает об отсутствии активной синхронизации; NevroTick автоматически не возвращается вторым контроллером.

Работающий W32Time отдельно от подтверждённого владельца и проверенной синхронизации. После передачи нет унаследованной точности, NTS-аутентификации или голосов NevroTick. Его профили, источники, интервалы и восстановительные настройки сохраняются с указанием области применения; они не становятся политикой Windows Time. Прежние измерения, подписи Roughtime, интервалы, возраста и потраченные бюджеты сохраняются как история. Возврат к NevroTick не создаёт свежих измерений и мгновенного зелёного статуса.

Неизвестные и частичные результаты согласованы в Simple, Status, Settings, Sources, Statistics, Diagnostics, Date recovery, нижней строке и экспорте. Pending сохраняется при навигации. Отмена диалога не отправляет команду, а сброс сцены предупреждает о потере незавершённого примера.

## Windows Time и другие службы

Официальные документы Microsoft не дают основания принудительно переводить все связанные службы в Automatic. **Manual/trigger-start допустим для W32Time**, в том числе на компьютерах вне домена. Изменение типа запуска не доказывает запуска и синхронизации. [Microsoft: W32Time на workgroup-компьютере](https://learn.microsoft.com/en-us/troubleshoot/windows-client/active-directory/w32time-not-start-on-workgroup).

Требуемые службы нужно получать из фактической конфигурации, например `QueryServiceConfigW.lpDependencies` или read-only `Get-Service W32Time -RequiredServices`. Допустим запуск demand-start-зависимости без перевода её в Automatic. Недоступная или запрещённая зависимость требует конкретного диагноза и ограниченного плана; массового включения служб и угаданного списка RPC/Netlogon в интерфейсе нет. Пример готовности показывает отсутствие дополнительных изменений, а отдельная сцена позволяет проверить блокировку по зависимости. [Microsoft: конфигурация службы](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/ns-winsvc-query_service_configw).

Сохраняются существующие серверы, доменная иерархия NT5DS, провайдеры, триггеры и действующая организационная политика. Само наличие GPO не запрещает разрешённую операцию; блокируется конкретное противоречие effective policy. Нет unregister/register, сбрасывающего конфигурацию. [Microsoft: настройки Windows Time](https://learn.microsoft.com/en-us/windows-server/networking/windows-time-service/windows-time-service-tools-and-settings).

Полное исследование с официальными источниками и границами будущей Windows-проверки: [WINDOWS-TIME-RESEARCH.md](WINDOWS-TIME-RESEARCH.md). Подробный контракт макета: [SPEC-RU.md](SPEC-RU.md).

## Проверка

Результаты финального кандидата и его точная идентичность записаны в [verification-summary.json](verification-summary.json). Независимые проверки: [исходный код и смысл состояний](SOURCE-REVIEW-RU.md), [браузерный проход](BROWSER-QA-RU.md).

На финальном source `c6e0801` прошли **175/175** тестов без пропусков, **1 088** структурных вариантов и выделенный браузерный набор управления временем для обоих HTML на 360/1280 px. Независимая приёмка подтвердила финальное исправление журнала для обоих HTML на 360/480/1280 px; исходный широкий проход сохранён для неизменной остальной логики. Нет открытых материальных замечаний в пределах этих проверок. CSP соответствует скрипту, исходные AVIF сохранены; ошибок JavaScript и неожиданных удалённых запросов в принятых браузерных наборах нет.

Во время review исправлены ложное полное отключение после неизвестного повторного включения, активная маркировка сохранённых NevroTick-настроек при владельце Windows, ошибочное глобальное предупреждение о паузе при остановке NevroTick-наблюдателя и текущая маркировка прежнего runtime во время ожидания ответа. Финальный браузерный аудит также обнаружил, что старые события Diagnostics могли читаться как текущая синхронизация: журнал получил собственную маркировку retained/pre-operation и пояснение возраста. Исходные сообщения и значения событий сохранены.

## Границы

Это интерактивные HTML-сценарии. Здесь не исполняются SCM/UAC, операции служб/реестра/часов и сетевые запросы времени. Linux/Chromium не подтверждает действительную Windows-политику, граф зависимостей, защищённое владение, освобождение часов, порядок и восстановление нативной транзакции или точность времени. Эти проверки потребуются при реализации настоящего интерфейса после утверждения прототипа.

Установленный облачный Chromium запрещает прямое открытие `file://` административной политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`). Визуально проверены HTML, открытые через локальный HTTP; автономность ресурсов подтверждена структурно. Это ограничение среды, а не выполненная проверка двойного щелчка в обычной Windows.
