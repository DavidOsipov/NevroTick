# Полное отключение, автозапуск и передача управления временем

Прямое поручение владельца: дать полностью отключить NevroTick, включать/выключать его автозапуск и передавать управление Windows Time. Это расширение HTML-прототипа. Не изменять /workspace/NevroTick, Windows, службы, реестр или часы; ничего не публиковать.

База: local351c1f2, standalone387bfa86331d45975f6b7b9142a92efa6487511f8eb343f3e452c9363d09230c. Текущая копия /workspace/nevrotick-ui-audit/ownership-work/NevroTick-UI-v0.4.

## Пользовательская модель

В одном Settings → Background service отделить:

1. **Состояние фоновой работы** — существующие Start / Stop / Restart / Diagnose. Stop временный, не меняет автозапуск.
2. **Start automatically with Windows** — администраторский переключатель автозапуска согласованной пары служб NevroTick. Off означает manual/on-demand, не останавливает уже работающие службы. On включает следующий автоматический запуск, не изображает уже выполненный Start. Пока неизвестно/запрос pending, не показывать ложный On/Off.
3. **Disable NevroTick** — прекратить фоновую работу и запретить запуск обеих служб; завершить только подтверждённо принадлежащее NevroTick управление часами. Отдельное подтверждение с последствиями. Это не установка/удаление программы и не неявное включение W32Time. Когда Windows Time не активен, ясно сообщить об отсутствии автоматической синхронизации. Если cleanup не подтверждён, не объявлять полное безопасное отключение.
4. **Time management** — кто сейчас управляет временем: NevroTick / Windows Time / no active synchronizer / unknown. Отдельное Use Windows Time выполняет согласованный переход; для обратного пути дать явное Use NevroTick. Автозапуск и Start никогда сами не перехватывают часы у другого владельца.

Интерфейс краткий, без roadmap/SCM/API-прозы и произвольных имён служб. В Simple — сводка текущей фоновой работы/владельца/автозапуска и ясный переход к управлению в Power. Не добавлять технические переключатели зависимостей Windows.

## Факты состояния

Разделять текущее выполнение служб NevroTick, их startup mode (automatic/manual/disabled/unknown), текущего владельца часов, наблюдаемое состояние W32Time, его Windows/policy-managed режим запуска и пригодность Windows-синхронизации. Эти величины не выводятся друг из друга.

Данные — явно демонстрационные наблюдения. Default example может показывать NevroTick running/automatic/verified current owner, W32Time stopped+disabled by the product и ранее допустимый Manual(trigger-start) режим. Это не универсальные defaults Windows. Не выбирать реальные серверы Windows, domain peers или дополнительные зависимости.

Полное отключение подтверждено только если оба сервиса остановлены, их старт запрещён (включая отложенный recovery restart) и корректное завершение принадлежащего NevroTick управления подтверждено. Оно сохраняет настройки, историю, authentication age и consumed budgets. Остановка/конфигурация служб сами по себе не доказывают cleanup или точность времени.

Start после полностью disabled требует явно подтвердить **Enable and start**: обе службы переводятся в manual и запускаются для текущего сеанса, автоматический запуск остаётся Off, если пользователь отдельно его не включил. Когда Windows Time владеет временем, NevroTick может запускаться только для наблюдения; Windows Time не выключается от Start/автозапуска.

## Настройка автозапуска

Запрос конфигурации — отдельный kind от runtime/ownership. Pending/неизвестный результат изменения startup не превращает текущую работающую синхронизацию в unknown и не останавливает активный DEBUG-сеанс. Успех меняет только подтверждённую startup-конфигурацию; Off не подменяется остановкой, On не подменяется Running. Отмена/отказ до исполнения сохраняет прежние факты. Неизвестную новую startup-конфигурацию показывать как unknown, а не откатывать к старому значению без наблюдения.

Один изменяющий запрос одновременно. Диагностика остаётся доступной без повышения прав. Пока конфигурация неизвестна, не повторять её изменение вслепую. При передаче управления Windows Time автозапуск NevroTick должен быть disabled/inhibited, чтобы не возникло второго писателя после reboot/recovery.

## Передача Windows Time

Опирается на WINDOWS-TIME-RESEARCH.md и каноническую архитектуру §10–11/19.2. Предыдущая отсрочка обратной передачи не блокирует текущее явное поручение для HTML.

Перед подтверждением показать краткий план с опубликованной готовностью/политикой: обе службы NevroTick будут остановлены/disabled; только принадлежащее им управление будет завершено; Windows Time будет включён/запущен с существующей разрешённой конфигурацией. Принадлежность и readiness проверяются заново, не берутся из одного старого saved owner. Само управление Windows Time через GPO не запрещает разрешённое восстановление: блокирует конкретный конфликт с effective policy, а не факт наличия организации.

Порядок intended transaction: preflight policy/dependencies/ownership → quiesce NevroTick и его queued restart paths → подтверждённое ownership-aware завершение его clock work/освобождение управления → stop+disable product services → enable/start W32Time по разрешённой Windows-конфигурации → подтвердить итоговые факты. До квалифицированного освобождения не запускать второго писателя. Прототип лишь показывает эти стадии/результаты.

- Не принуждать W32Time к Automatic: Manual/trigger-start допустим и зависит от машины/политики.
- Не перезаписывать peers, NT5DS/domain и GPO; старый сохранённый snapshot не выше последующего решения администратора.
- Проверять реальные prerequisites через Windows service configuration. Никакого угаданного списка RPC/других служб и массового включения. Если prerequisite требует разрешённого изменения, оно должно быть явно перечислено в плане; если запрещено/неизвестно — блокировать до изменений. Default sample: проверка готовности завершена, дополнительных изменений служб не требуется; это только пример.
- Blocked-by-managed-policy / policy conflict / unavailable dependency / uncertain ownership должны иметь воспроизводимые preview-сценарии и понятную причину отказа до изменений. Их можно задавать только внешней reviewer-панелью, а не выбором результата внутри приложения.
- Completed handover означает **независимо подтверждённое освобождение и передачу владельца**, а не только Running W32Time. Вывести Windows Time manages time; синхронизация Windows ещё не проверена. Не переносить в неё прошлый статус NTS/голоса/offset.
- Если часть действий выполнена, показывать подтверждённые части и unconfirmed/partial итог. Например NevroTick stopped+disabled, но cleanup не подтверждён — Windows Time не запущен; либо cleanup подтверждён, но W32Time не запустился — нет активной синхронизации. Не объявлять успех и не автоматически возвращать опасного конкурирующего писателя.
- Lost acknowledgement означает unknown, без слепого повтора. Доисполнительная отмена/отказ не меняют источники/службы/владельца/диагностику.

Use NevroTick — отдельный подтверждённый обратный переход только при разрешённой политике и текущем подтверждении владельца. Остановить и отключить запуск W32Time на время владения NevroTick (чтобы triggers/autostart не вернули конкурента), сохранить его настройки для будущего восстановления, подтвердить передачу NevroTick и запустить его пару. Вновь включённые службы могут оставаться manual, если autostart пользователь оставил Off. Возврат не означает готовую синхронизацию: нужны новые пригодные измерения. Не добавлять неявную передачу при переключении профиля Observe-only или обычном Start.

## Вся презентация должна быть согласованной

Status, Settings, Sources, Statistics, Diagnostics, footer, export и самостоятельные диалоги используют одни факты. При Windows Time owner: NevroTick services могут быть disabled/stopped, а основной статус не должен утверждать отсутствие вообще всех контроллеров; текущая NTS-синхронизация NevroTick не утверждается. При запуске NevroTick для наблюдения Windows остаётся владельцем. При fully disabled/no active synchronizer показать прямое предупреждение о прекращении автоматической синхронизации.

Roughtime/NTS остаются историей после runtime/ownership операций. Прежние стадии не называются текущими. Сигнатуры/интервалы/ancestry/история не удаляются и не приобретают свежесть. Startup-only не является таким runtime-событием и не инвалидирует время или сбор диагностики.

Закрытие диалога не теряет pending, Cancel/Escape не отправляет команду, недоступный после запроса control не забирает фокус в BODY. Сброс reviewer-сцены предупреждает о потере pending/локальных данных. Все исходы и preflight условия проверяемы снаружи приложения; не имитировать настоящие службы, системные таймеры, UAC или registry/SCM calls.

## Приёмка

- Running+automatic → autostart Off сохраняет Running/текущий clock status/DEBUG; On не запускает stopped pair.
- Disable → подтверждённые stopped+disabled+cleanup; no active sync только если другого подтверждённого синхронизатора нет. При Windows owner отключение наблюдающего NevroTick сохраняет Windows owner/status. Cancellation сохраняет всё; partial не выдаётся за full disabled.
- Enable and start → manual/running, не automatic и не instant synchronized; Windows owner не перехватывается.
- Use Windows Time: ready/allowed completion, GPO/dependency/ownership preflight block до изменений, partial/unknown, W32Time running не равно synchronized.
- После handover Windows владелец отражён во всех views/export, product startup disabled; explicit reverse transfer reacquires без старой синхронизации.
- Ни startup, ни handover не обходят read-only/authority, не меняют Windows peer/domain policy и не включают неизвестные службы.
- Сохранены все baseline155 tests, предыдущие service/DEBUG/Roughtime/focus/reset invariants. Meaningful model/render и targeted Chromium360/1280 обоих HTML; скриншоты осмотреть. Независимые code review и browser QA, финальная CSP/AVIF/structural/package проверка.
