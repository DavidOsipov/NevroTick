The pinned [Rustls connection API](https://github.com/rustls/rustls/blob/f04804fa13341a9b1dc02b5d1dd8a746f2c4b7fb/rustls/src/conn.rs)
exposes `export_keying_material(output, label, context)`. Context7 returned newer
`main` documentation with a different `exporter()` API; it was used for discovery
and rejected as version-specific evidence. The pinned source controls this card.

For NTS algorithm 15, [RFC 8915 §5.1](https://www.rfc-editor.org/rfc/rfc8915.html#section-5.1)
requires exporter label `EXPORTER-network-time-security` and contexts
`00 00 00 0f 00` (C2S), `00 00 00 0f 01` (S2C), with separate 32-byte keys.
[`Aes128Siv`](https://github.com/RustCrypto/AEADs/blob/e1b1e6e312b00f2ce7a2fc02d208681fb5d25f64/aes-siv/src/siv.rs)
is the candidate for the 32-byte total key; `Aes256Siv` and AES-GCM-SIV are different
algorithms. Its low-level SIV API accepts separate associated-data components;
freeze the RFC 8915 packet/nonce mapping before integration and verify RFC 5297
known-answer vectors plus independent NTS peer output. The README explicitly
disclaims an independent audit and complete constant-time assessment.

Microsoft's [standard CNG identifier table](https://learn.microsoft.com/en-us/windows/win32/seccng/cng-algorithm-identifiers)
lists AES and AES-CMAC but no AES-SIV identifier. This is a bounded documentation
observation, not a proof about every third-party provider. CNG TLS support does
not remove the separate NTS AEAD admission gate; do not compose a new SIV primitive
from native AES/CMAC calls to work around it.

## Bounded second route: Schannel source feasibility only

The acquired `schannel 0.1.30` source has TLS 1.3 protocol selection and ALPN
request/query APIs. Scanning all packaged Rust source found no `KEYING_MATERIAL`,
`export_keying` or `exporter` occurrences. The ordinary stream API is therefore
not evidence of an NTS exporter integration. The pinned wrapper remains a source
comparison, not an adopted replacement or executed second prototype.

Microsoft documents [setting exporter inputs](https://learn.microsoft.com/en-us/windows/win32/api/schannel/ns-schannel-secpkgcontext_keyingmaterialinfo),
[querying exported material](https://learn.microsoft.com/en-us/windows/win32/secauthn/querycontextattributes--schannel)
and [freeing its output with FreeContextBuffer](https://learn.microsoft.com/en-us/windows/win32/api/schannel/ns-schannel-secpkgcontext_keyingmaterial).
The label length includes its NUL terminator; Schannel removes it before key
derivation. Query requires the material-info attribute and a generated master
secret. These APIs document RFC 5705 support; they do not establish exact TLS 1.3
NTS exporter semantics, peer interoperability, buffer lifetime or service trust.
If the first route fails, a narrow reviewed SSPI/exporter adapter or qualified
upstream wrapper enhancement must satisfy those same gates. Do not alter global
Schannel protocol policy.
