## Protocol and errata check

Fresh RFC Editor errata pages were retrieved on 29 October 2026:
[RFC 5905](https://www.rfc-editor.org/errata_search.php?rfc=5905) and
[RFC 8915](https://www.rfc-editor.org/errata_search.php?rfc=8915). The latter
reported no matching errata. The former distinguishes verified, held and rejected
records. In particular, verified [EID 3007](https://www.rfc-editor.org/errata/eid3007)
means RATE increases the polling interval. Rejected EID 3613 and EID 4505 are
not accepted textual replacements; their timestamp/state-order concerns still
motivate independent tests against NevroTick's current contracts.

[RFC 8915 §4](https://www.rfc-editor.org/rfc/rfc8915.html#section-4) uses **SHOULD**
for clients accepting responses of at least 65,536 octets, versus **MUST** for
servers accepting requests of at least 1,024. NevroTick's architecture preserves
the larger response-acceptance target. EOM has a zero body and critical bit;
§5.7 requires discarding unauthenticated extensions. These are separate from
total-message and current-generation checks.

## Independent literal oracle specifications

These are fixture specifications and independently checked rational arithmetic,
not behavioral RED/GREEN. The future producer must be the real bounded packet
entry point, followed by the real exchange-admission consumer. No such core
exists yet. Proposed entry-point names remain in the coordinator's S1.1 card.
All rejection cases must preserve a healthy outstanding exchange/history/cookies
and be followed by acceptance of a current valid neighbor exactly once.

**Symmetric valid control:** explicit plain-NTP fixture profile, current logical
source/endpoint/configuration/association/clock generations, unexpired monotonic
deadline, one outstanding request. Saved real T1 and wire token are both
`e000000000000000`; local T4 is `e00000001c28f5c2`.

```text
24 02 06 ec 00 00 00 00 00 00 00 00 47 50 53 00
df ff ff ff 00 00 00 00 e0 00 00 00 00 00 00 00
e0 00 00 00 11 eb 85 1e e0 00 00 00 14 7a e1 47
```

This is a 48-byte NTPv4/server packet, synchronized LI, stratum 2, poll 6,
precision -20. Relative ideal times are 0/70/80/110 ms: +20 ms offset and
100 ms delay. Q32 timestamp fractions floor the ideal millisecond values.
Therefore exact encoded expectations are offset `171798691 / 8589934592`
seconds and delay `429496729 / 4294967296` seconds. Their decimal presentations
are approximately +19.99999990221113 ms and 99.99999986030161 ms. Preserve the
rationals and declare checked rounding when selecting the output unit.

**Randomized-token control:** replace origin bytes 24–31 with
`01 02 03 04 05 06 07 08`, set saved expected wire token to those bytes, retain
the same real T1. Expected offset/delay are unchanged. Substituting the origin
token into arithmetic fails this case.

**Asymmetry control:** true server offset remains +20 ms, forward/reverse network
delays are 30/70 ms, processing is 10 ms. Set T2 fraction to `0ccccccc` and T3
fraction to `0f5c28f5`; retain seconds/T1/T4. Encoded offset is
`-1 / 8589934592` seconds (ideal 0 ms), with the same encoded delay. This proves
the expected -20 ms estimation bias; authentication cannot remove it.

| Case family | Independent input and expected observation |
| --- | --- |
| Truncation/alignment | Valid header truncated to 47 bytes; extension claiming 35 bytes or extending past actual remaining bytes. Reject before out-of-bounds access/allocation/state publication. Pair with the complete valid header and separately valid aligned extension. |
| Wrong mode/version/sync | Change first byte to `23` (client mode), `1c` (v3) or `e4` (LI unsynchronized). Reject as an eligible NevroTick v4 time observation. The v3 row is product scope, not a claim every upstream rejects v3. |
| Correlation and replay | Flip the last origin byte with all context fixed; replay the complete accepted valid packet; present correct bytes with a stale association/configuration/clock generation. No additional accepted observation or cookie commit; a new current request succeeds. |
| KoD | Stratum zero and reference ID `52 41 54 45` (RATE) is control, never time; wrong-correlation RATE changes neither polling nor sample state. A correlated admitted RATE increases interval under a separately frozen policy, not an invented fixed interval. |
| Rollover | Explicit unfolded tuples `(era, seconds, fraction)`: T1=`(0,ffffffff,f8000000)`, T2=`(1,00000000,08000000)`, T3=`(1,00000000,18000000)`, T4=`(1,00000000,28000000)`. Exact offset 0 and delay 1/8 second. Every essential wire timestamp is nonzero. |
| Ambiguous era/overflow | Reuse rollover wire bytes without a trusted era anchor; use differences at/around the signed half-era ambiguity; convert just inside/outside the selected target-date/unit range. No guessed calendar era, unchecked subtraction or automatic-step authority. Exact acceptance boundaries await the era/date contract. |
| NTS atomicity | Wrong UID/tag/key/origin, duplicate UID/cardinality, malformed encrypted field and stale association must cause no sample/cookie/key commit. Requires an admitted AEAD graph and literal independently sourced crypto known-answer bytes; none were generated here. |
| KE framing | Literal EOM `80 00 00 00` is the valid shape; `00 00 00 00`, `80 00 00 01 00`, missing/truncated EOM, duplicate required records, unknown-critical `ff ff 00 00` and unoffered selections need distinct receiver cases. Pair unknown critical with inert unknown-noncritical `7f ff 00 00`. Include total sizes 65,535/65,536/65,537 and just below/exact/above the adopted final cap with complete valid framing. ## Replay and delayed-response qualification

**31 October 2026 — explicit acceptance refinement, not executed NTS evidence.**
The [architecture's NTS contract](../docs/windows-time-architecture.md#74-nts-implementation-contract)
already requires fresh CSPRNG UIDs, authenticated responses and bounded current
state. Make the following lifecycle and timing cases explicit for S2.2–S2.4,
using [RFC 8915 sections 5.3/5.7](https://www.rfc-editor.org/rfc/rfc8915.html#section-5.7)
and [section 8.6](https://www.rfc-editor.org/rfc/rfc8915.html#section-8.6).
Keep CHECK-6/7/8/9/21 and the existing P1 simulator/P2 protocol owners; this creates
no new acceptance identifier, shipping constant or clock-write authority.

| Case | Independent expected observation and healthy control |
| --- | --- |
| Recorded response after completion or during a new query | Replay a previously accepted protected response, including while another UID is pending. No additional sample, cookie commit or freshness refresh; the genuine current response completes once. |
| Repeated or racing copies | Deliver two valid copies before final publication, including through any asynchronous verification seam. Final owner revalidation permits one completion only. Wrong-UID/tag/key traffic cannot consume the healthy current request; genuine expiry/cancellation retains its separate retirement behavior. |
| Expiry and queued processing | Test arrival and processing just below, exactly at and beyond the qualified deadline. A packet arriving before expiry but processed at/after expiry publishes no protected result. A completely validated neighboring response processed before expiry succeeds. UTC adjustment cannot extend the monotonic deadline. |
| Restored keys/cookies and lifecycle | Replay captured replies after same-boot restart with qualified cached secrets, suspend/resume and association/clock-generation changes. No old exchange is restored or revived; a newly issued fresh UID with current context succeeds. Internal counters absent from the wire cannot disambiguate reused correlation values. |
| First delivery delayed within a current request | Keep the genuine response's UID, protected bytes and tag unchanged while delaying its first arrival. Where the frozen delay/uncertainty/deadline policy permits the sample, authentication may succeed; independently calculate its offset bias and uncertainty. Do not claim the delay must be cryptographically detectable. |
| Delay or uncertainty outside policy | Exercise just below/exact/above the independently frozen hard limits. Out-of-policy packets supply no eligible sample or correction; admissible neighboring traffic remains useful. Preserve Chrony precision/frequency semantics rather than inventing a negative-RTT shortcut. |
| Common-path interference and outage | Delay traffic from several independent operators through one shared path and separately suppress other sources. Preserve configured minimum agreement, uncertainty aging and correction budgets; no automatic single-peer or plain-NTP fallback. Record any bias still allowed by the declared path assumptions. |
| Replay flood and recovery controls | Bound packet work, pending state, counters and diagnostics. Uncorrelated/replayed NAKs cannot publish time/cookies, refresh accepted-observation age or create unbounded KE work. Test the separately admitted correlated control path and continued genuine protected replies; a blanket AEAD requirement on KoD would be incorrect. |

For an analytic illustration, retain the known true +20 ms server offset and
`T1/T2/T3/T4 = 0/70/80/110 ms`, then add 100 ms only before delivery of the reply:
`0/70/80/210 ms` yields estimated offset **-30 ms**, network delay **200 ms** and
offset bias **-50 ms**. These are relative coordinates, not zero-valued wire
timestamps or an approved latency allowance. Produce valid wire/crypto vectors
separately and choose admitted neighbors from the frozen policy. Real server
accuracy, source uncertainty and holdover error remain separate from this example.

These cases complete the distinction missing from the earlier generic replay and
asymmetry rows. The current unauthenticated `ntp-exchange` fixture has useful
once-only/deadline controls but explicitly permits caller-supplied token reuse;
it cannot qualify the production UID issuer or NTS authentication. Production
timing/uncertainty/quorum/correction values remain OPEN-5/6 decisions. P2 uses
controlled peers without developer-clock effects; actual broker enforcement
retains its P4/native qualification.
