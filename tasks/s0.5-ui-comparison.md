### Native Windows pilot

The ordinary-user Windows session reports build `10.0.26300.0`, 16 logical
processors and system DPI 144. Both candidates ran sequentially on that same
host with a fixed three-second warmup and ten-second visible/minimized idle
intervals. Win32 is currently DPI-unaware (window DPI 96); egui is per-monitor
aware (window DPI 144). Rendering configuration, window sizes and cache state
are recorded, not normalized away. Hardware/GPU-driver identity and GPU/system
memory were not measured; no universal toolkit footprint follows.

Final selected receipts: `win32-observations-4` and `egui-observations-5` under
`%LOCALAPPDATA%\NevroTick\ui-compare-20261030-*`.

| Process private bytes, selected warmed/visible/restored/page snapshots | 2.05–2.20 MiB | 133.04–144.88 MiB |

The startup proxies include process/token/module/window selection and provider
observation overhead; they are not controlled cold-start measurements or p95
acceptance tests. Memory values are snapshots, not sustained p95 or leak/soak
evidence. Egui also measured 131–143 MiB in the earlier correctly selected-window
run. These observations give a resource-fit concern against the proposed 48 MiB
visible-UI budget without claiming full CHECK-21 qualification.

Visible idle CPU was about 0.16% of one logical core for Win32's final ten-second
interval and 0% for egui's final interval. An earlier valid egui interval measured
about 1.25%; all final minimized intervals measured zero accumulated CPU time.
Such short, quantized observations do not establish a stable CPU ordering,
zero-power behavior or continuous-rendering overhead. No CPU speedup claim is made.

The .NET client-side UIA provider registration failed in this environment.
Consequently, Win32's missing managed-client action patterns are a tool/environment
gap, not evidence that Win32 controls lack accessibility. Its fallback establishes
the actual view transitions only. Egui supplied actionable toggle nodes through
its native AccessKit provider. Neither observation establishes complete keyboard,
Narrator, contrast, text scaling or mixed-monitor behavior.

Native editor valid-update / rejection-preservation / Cancel were **not exercised
in this comparison**; the portable session/model tests supply narrower evidence.
Tray, UAC, reconnect, renderer/device loss, RDP, power, complete MSI and long-run
observations are also absent. No service, clock, policy, trust-store or machine
preference changes were made. Only the observer's process DPI context was selected
to qualify screenshot coordinates.

### Dependency and license finding

The filtered Windows graph resolves **125 packages: the local candidate plus 124
registry packages**. All 16 existing UI cohort packages recur at identical
versions/checksums, with 108 new registry packages. Independent inspection verified
all 124 archive checksums and 6,044 extracted source files (228,867,637 bytes)
against their archives; inspected 20 build scripts and nine proc-macro source
trees. No downloader, external acquisition or C/C++ compilation path was found in
that bounded review. This is not an assurance that dependencies are defect-free;
no complete fresh advisory/vet/license-distribution qualification was executed.

Although egui/eframe offer `MIT OR Apache-2.0`, selected normal Windows runtime
paths include Apache-2.0-only grants:

| Package | Version | Path / consequence |
| --- | --- | --- |
| `winit` | 0.30.13 | Required directly by native eframe and egui-winit |
| `unicode-general-category` | 1.1.0 | Required by epaint, independent of renderer |
| `accesskit_winit` | 0.34.2 | Required by the selected accessibility feature |
| `glutin`, `glutin_egl_sys`, `glutin_wgl_sys` | 0.32.3 / 0.7.1 / 0.6.1 | Added by the selected Glow branch |

These normal paths exclude the separate build-only Apache tooling. `dpi 0.1.2`
also carries an `Apache-2.0 AND MIT` conjunction. Inspected manifests/source
notices and license texts disclosed no general alternative grant for the listed
Apache-only code. Pinned primary examples:
[winit](https://github.com/rust-windowing/winit/blob/e9809ef54b18499bb4f2cac945719ecc2a61061b/Cargo.toml#L373),
[Unicode category](https://github.com/yeslogic/unicode-general-category/blob/cb2d8a62f035c33d6971b99322aae65f3cea7c88/Cargo.toml#L12),
[AccessKit adapter](https://github.com/AccessKit/accesskit/blob/f3026222559c7f5f46d8f25cb7404de68eb149f0/adapters/winit/Cargo.toml#L5).

[ASF compatibility guidance](https://www.apache.org/licenses/GPL-compatibility.html)
and architecture §18.3 make this an adoption/distribution concern for the current
GPL-2.0-only combination. Switching to wgpu removes the glutin branch but retains
winit and Unicode-category code; disabling AccessKit alone also does not resolve
the graph. Choosing egui's own MIT option cannot change its dependencies' grants.

This user-authorized private experiment does not distribute or admit that graph;
[GNU's private-use guidance](https://www.gnu.org/licenses/gpl-faq.en.html#GPLRequireSourcePostedPublic)
supports the distinction. A future independently licensed UI arrangement, compatible
grants or replacements needs concrete ownership/rights and distribution review.
An IPC/process split alone supplies no automatic legal clearance, and this record
does not change Chrony's GPL-2.0-only provenance or relicense any component.
