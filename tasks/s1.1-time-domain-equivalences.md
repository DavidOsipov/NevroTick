## TD-E-001 — disjoint bit-field OR and XOR

Exact mutation:
`crates/time-domain/src/era.rs:115:53: replace | with ^ in unfold_ntp`.
Diff SHA-256:
`ba48746676533078b3918164e3277e603584f921a701ae56789d0d4ccf03c0e2`.

Requirement: preserve all raw u32 seconds/fraction bits exactly (CHECK-6/7/25).
Both inputs have type `u32`; widening to `u64` preserves their unsigned value.
Let `a = u64(seconds) << 32` and `b = u64(fraction)`.
Every set bit of `a` lies in positions 32–63; every set bit of `b` lies in
positions 0–31. Consequently `a & b = 0` for every one of the 2^64 input pairs,
and `a | b = a ^ b`. Both forms produce the same u64 value. Widening that result
to i128 is exact; every subsequent operation is unchanged. No valid or invalid
window, error path, output or permitted effect distinguishes this exact single
operator mutation.

## TD-E-002 — final era-membership predicate

Exact mutation:

Diff SHA-256:
`7b48eaf3f3d0b0670fd7715944f7503c4ec5bfada8fd668ce879438664a9624e`.

Requirement: publish a coordinate only when the explicit inclusive window has
one exact unfolding; distinguish absence and ambiguity (CHECK-6/7/25).
Let `r` be the unchanged raw timestamp, `M = 2^64 > 0`, and `[L,U]` the private
checked window with `L <= U`. The unchanged checked Euclidean calculations give
`first = ceil((L-r)/M)` and `last = floor((U-r)/M)`.
Every earlier error/absence/ambiguity path is identical in the two programs.

ceiling and floor, `L-r <= k*M <= U-r`, so `L <= r+k*M <= U`.
Checked reconstruction either returns the same earlier arithmetic error, or
produces exactly `ticks = r+k*M` within the window. Therefore the original
predicate `ticks < L || ticks > U` is false on every reaching execution; the
mutated `ticks < L && ticks > U` is also false. Both continue into the same
checked coordinate constructor. The retained guard remains useful defense and
documentation; an additional test cannot distinguish this exact single mutation
without changing the admitted input/type/algorithm contract.

## Shared rounding argument for TD-E-004 through TD-E-006

Requirement: nearest-ties-even signed-i64 nanoseconds with exact bounded signed
residual, no allocation or effects (CHECK-6/7/25). The private `round` helper
accepts **every i128 numerator**, with `Scale::Phase` or `Scale::RoundTrip`.
The proof covers that complete helper domain, not only numerators obtainable
from the public exchange API.

Any earlier checked multiplication/operation failure or out-of-i64 destination
returns the same error before the changed predicate. On every reaching execution,
let `D` be the unchanged scale denominator, either `2^33` or `2^32`, and `h=D/2>0`.
Write the checked scaled numerator as `z=f*D+r` by Euclidean division, with
`0 <= r < D`. Let `q` be the unchanged rounded result and `e=z-q*D` its residual:

| Unchanged rounding case | Rounded result | Exact residual and parity |
| --- | --- | --- |
| `r < h` | `q=f` | `0 <= e < h` |
| `r > h` | `q=f+1` | `-h < e < 0` |
| `r = h`, `f` even | `q=f` | `e=h`, `q` even |
| `r = h`, `f` odd | `q=f+1` | `e=-h`, `q` even |

This includes negative numerators/floors because Euclidean remainder is
nonnegative and the existing parity comparison checks nonzero remainder modulo
two. Thus every reaching residual lies in `[-h,h]`, and either endpoint has an
even destination. The two original rejection operands are always false.
Fixed positive denominators, representable `-h` and division by two make these
comparisons total; changing their short-circuit evaluation introduces no effect.
