## Frozen numerical engineering contract proposed for review

Names below are proposed API names; the units, roles and guarantees are binding
for this card if adopted.

| Owner/type or operation | Exact input/output contract |
| --- | --- |
| `UtcCoordinateQ32` | Private `i128` ticks, each `1 / 2^32` second, with the NTP epoch as explicit coordinate origin. Constructor accepts only `-2^95 ..= 2^95 - 1`, corresponding to signed-i64 whole seconds plus u32 fraction. It represents an unfolded claimed UTC coordinate, not proof of true UTC. |
| `EraWindow::new(earliest, latest)` | Inclusive endpoints within that coordinate envelope and `earliest <= latest`. The sole checked entry internally validates a fixed-field garde candidate and the shared cross-field rule before constructing the immutable window. No implicit default/pivot, local-date read or provenance claim. |
| `unfold_ntp(seconds, fraction, &window)` | Preserve raw u32 parts exactly. Let `r` be their unsigned-u64 combined bits and `M = 2^64` Q32 ticks. Solve `L <= r + k*M <= U` for integer era `k`. Return the unique checked in-window coordinate; reject zero candidates and multiple candidates distinctly. |
| `exchange_arithmetic` | Accept named roles `real_t1`, `peer_t2`, `peer_t3`, `local_t4`, all in the stated common coordinate system. The function never derives `real_t1` from packet origin; it cannot certify the provenance of an ordinary coordinate argument. Supplying the saved real transmit coordinate is a caller obligation enforced by the later exchange-association owner. Return exact offset and signed raw RTT without state effects or sample admission. |
| `PhaseOffsetQ33` | Numerator `n = (T2 - T1) + (T3 - T4)` over `2^33` seconds. Positive means local Windows time is behind. An odd Q32-difference sum retains its half-tick; do not truncate it to Q32 before returning. |
| `SignedRoundTripQ32` | Numerator `d = (T4 - T1) - (T3 - T2)` over `2^32` seconds. Preserve negative results. Do not add an unconditional negative-delay rejection or precision clamp. |
| Clock-domain types | Distinct UTC coordinates, `MonotonicNs` and `ActiveAwakeNs`, with explicit units/fixture origins and no implicit cross-domain conversion. Elapsed operations accept only matching domains, check ordering/overflow and preserve the elapsed domain in their results. No wall-clock step can extend a monotonic deadline through a conversion here. |

The coordinate envelope is a finite **numeric engineering bound**, not an approved
supported true-date interval, maximum local clock error, recovery/step ceiling or
Windows conversion range. It does not select leap/smear policy or a native clock
mapping. Tests explicitly supply a common non-leap fixture coordinate system;
production adapters must qualify their actual mapping and time scale later.

Use checked integer operations and constructor postconditions throughout.
Endpoint differences have magnitude at most `2^96 - 1`; the offset numerator
and raw RTT numerator have magnitude at most `2^97 - 2`. Preserve these result
invariants. No floating timestamp, silent saturation, fallback success or
release-disabled assertion supplies required enforcement.

Era resolution computes candidate bounds with checked Euclidean arithmetic:
`k_min = ceil((L - r) / M)` and `k_max = floor((U - r) / M)`.
`k_min > k_max` means no admissible era; `k_min != k_max` means ambiguity.
Otherwise check `r + k_min*M` and its final range before publishing it. Use
constant work, not iteration over the number of eras in a hostile wide interval.
Negative intervals require Euclidean floor/ceiling semantics, not truncation
toward zero. No nearest-era or half-era tie-breaking fallback is selected.

### Explicit nanosecond rounding and residual

Convert relative offset/RTT to signed-i64 nanoseconds only through an explicit
**nearest, ties-to-even** operation. This is a mathematical conversion contract,
not an automatic correction or sample policy. For numerator `n` and denominator
`S` (`2^33` for offset, `2^32` for RTT):

1. Compute `z = n * 1_000_000_000` with checked arithmetic.
2. Round the signed exact rational `z / S` to nearest integer `q`, with exact
   halfway cases choosing the even integer; check that `q` fits i64.
3. Retain exact signed residual numerator `e = z - q*S`. Its units are
   nanoseconds divided by `S`, so the original value in nanoseconds equals
   `q + e/S`. Offset requires `-2^32 <= e <= 2^32`; RTT requires
   `-2^31 <= e <= 2^31`. At equality the rounded integer is even.

Private immutable results must make the residual's denominator unambiguous and
validate both destination and residual postconditions. Test positive/negative
ties, near ties, rounded zero and destination endpoints. Do not hide the
quantization residual when a later uncertainty calculation consumes the result.
Absolute UTC-to-FILETIME conversion and floating regression inputs are separate
future contracts; no NaN/infinity path is introduced by this integer-only slice.
