## Caller findings that constrain the next slice

1. The actual source-statistics path is `SST_DoNewRegression` →
   `RGR_FindBestRegression`, **not** a call to `RGR_WeightedRegression`.
   Both implement inverse-divisor weighted equations (`1/w`); larger `w` reduces
   influence. Calling it a precision multiplier reverses behavior.
2. The caller derives dimensionless divisors from peer distance, local precision,
   a median/spread calculation and a squared scale (sourcestats.c 528–550), then
   applies asymmetry correction before fitting. Those are source-quality policies;
   arbitrary fixture divisors do not qualify that derivation or malicious-peer
   uncertainty claims.
3. `convert_to_intervals` references the newest sample, giving nonpositive time
   differences. `SST_AccumulateSample` explicitly negates NTP offset: stored
   positive means local **fast**. NevroTick public positive means local **behind**.
   A future adapter must name/test its sign boundary for both intercept and slope;
   copying a source-statistics frequency sign is unsafe.
4. `RGR_FindBestRegression` adds residual-runs testing, optional earlier samples,
   iterative starting-index selection and result statistics. The caller prunes
   only after a successful fit and derives/clamps skew and standard deviations.
   The small weighted fit alone ports none of that behavior.
5. Canonical §17 caps regression history at 64 samples/source. Upstream also has
   64 current samples, but retains up to 64 additional samples for runs testing
   in some arrays (`REGRESS_RUNS_RATIO=2`). Do not infer permission for a new
   128-sample product store; all auxiliary retained samples need an explicit bound
   and review against the canonical cap before adoption.
6. Upstream accumulation resets history for duplicate/out-of-order sample time
   (sourcestats.c 300–305). A new raw invalid input must not gain that destructive
   side effect. Freeze a current-generation ordering/rejection contract before
   implementing history; record any intentional divergence in the same ledger.
7. Upstream minimum skew/standard deviation, worst-case fallbacks, confidence
   coefficients, asymmetry thresholds and fast-update exceptions are observed
   source policy, not adopted NevroTick constants or release guarantees.

### Frozen proposal for synthetic numerical behavior

All following numbers are test-kernel admission limits, not shipped oscillator,
source-history or correction policy. Raw field range endpoints are inclusive.

1. `3≤n≤64`. Each finite relative `x` is in `[-4096,0]` seconds, strictly
   increasing, with the final value exactly zero (either signed zero compares
   equal). Each finite positive-behind phase has `|y|≤1` second. Each finite

   input coordinates/phases explicitly; legitimate zero remains valid.
2. Let `H=-x[0]`; require `1/16≤H≤4096` seconds. Set `z_i=x_i/H`,
   `q_i=1/d_i`, `W=Σq_i` and `mu_z=Σ(q_i*z_i)/W`.
   Prepared geometry depends only on `x/d`, never `q*y`, a response mean or
   response covariance. Require finite normal-or-zero transformed coordinates
   and positive finite weight/denominator. No absolute timestamp enters these
   calculations.
3. In a second geometry pass compute `Szz=Σ(q_i*(z_i-mu_z)*(z_i-mu_z))`
   and `C=Szz/W`. Require the calculated binary64 `C≥1/256`, rejecting
   weaker geometry. After that checked geometry, `fit` first tests whether all
   admitted phase values are numerically equal, without an epsilon (signed zeros
   compare equal). If so, return the original constant and exact zero rate
   through checked result construction, without evaluating response sums. This
   is the exact constant-series solution, not a fallback after arithmetic failure.
   Otherwise compute `mu_y=Σ(q_i*y_i)/W` then
   `Szy=Σ(q_i*(z_i-mu_z)*(y_i-mu_y))`. For that nonconstant series return
   `B=Szy/Szz`, `A=mu_y-B*mu_z`, `phase_rate=B/H`. Public positive phase means
   behind; public rate is the derivative of that phase, without borrowing
   Chrony's opposite stored sign or a production frequency convention.
4. Accumulate left-to-right in the supplied strict chronological order, with
   each multiply/divide/add/subtract as a separately named binary64 operation;
   no explicit fused multiply-add, parallel/reordered reduction or fast-math
   optimization. Use the formula's written left association. Private retained
   compiler settings must preserve this arithmetic contract. The official
   [Rust numeric documentation](https://doc.rust-lang.org/std/primitive.f32.html)
   describes primitive-operation rounding; [f64](https://doc.rust-lang.org/std/primitive.f64.html)
   uses binary64 and distinguishes fused `mul_add`. Context7 supplied reference

   `algebraic_*` methods, whose documented transformations differ from these
   ordered primitive operations. Documentation lookup admits no graph or build.
   Scalar predicates
   and prepared geometry enforce it before fitting; finite checks protect
   transformed outputs, not merely input annotations.
5. Reject a nonzero subnormal intermediate/output and any multiplication or
   division that maps nonzero operands/numerator to zero as explicit unsupported

   covariance are legal. The constant branch above also permits an admitted
